# Williams AI v5 — глубокий аудит причин ошибок и корректирующих изменений

**Дата:** 2026-11-12. **Статус:** исследовательская ветка; в `main` ничего автоматически не переносить. **Реальная торговля:** ЗАПРЕЩЕНА.

## 1. Достоверная исходная база

- Исходный GPU запуск: [43094988456](https://github.com/19wolfalone92/Williams-AI/actions/runs/43094988456); он обучил Qwen3-4B QLoRA, но GitHub-этап экспорта ошибочно не принял файлы, поскольку нашёл повторяющиеся адаптеры среди промежуточных checkpoints.
- Исправленное восстановление и независимые CPU-проверки: [43151568333](https://github.com/19wolfalone92/Williams-AI/actions/runs/43151568333) и [43151575047](https://github.com/19wolfalone92/Williams-AI/actions/runs/43151575047). **80 фактических optimizer steps**; `adapter_model.safetensors` SHA256 `8bd26590df627c7452d56e81df6a4572885bfc82515259a7c9de4a3970c850b8`. Повторный GPU-запуск не понадобился.
- Validation loss: 3.718210 → 1.462684 (относительное улучшение 60.66%). Этот показатель **не доказывает** понимание графиков или торговую пригодность.
- Старый 16-кейсный экзамен: v5 без источников 14/16, с источниками **1/16**, **15 отказов/невалидных ответов** при работе с источниками; base соответственно 6/16 и 2/16. Старый checkpoint500: 9/16 без источников, 8/16 с источниками (только справочная величина).
- Новый rule-disjoint 28-кейсный тест: v5 11/28, base 8/28; TC2 4/8 против 3/8, NTD 4/8 против 1/8, TC1 2/8 против 2/8, COURSE 1/4 против 2/4. Это тесты разработчика с синтетическими перефразированиями, **не независимая экспертная оценка графиков**.

## 2. Установленные дефекты (корневые причины и последствия)

| Приоритет | Дефект и подтверждение | Коррекция |
|---|---|---|
| P0 | **Утечка подсказки из ID экзамена:** в `answer_exam_case` на вход нейросети передавался `id` вроде `NTD-AC`, `TC1-W5`, что могло указывать на нужное правило. Экзамен был менее «слепым», чем заявлялось. | Передаём нейросети только `edition/question/choices`, без `id` и эталонных ответов. Сравнение со старым checkpoint500 честно помечено несовместимым по протоколу декодирования. |
| P0 | **Разрыв контракта train/inference:** тренировочные MCQ задавались верхнеуровневыми `edition/question/choices`, а RAG-экзамен отправлял вложенное `case` и `prior_edition_scoped_lessons`. | Восстановлена единая форма верхнеуровневого вопроса; источники добавляются как данные `reviewed_source_context`, без изменения формы MCQ. |
| P0 | **Режим мышления Qwen мог исчерпывать бюджет 512 токенов:** ответ с `finish_reason=length` без финального JSON всегда считался отказом. Точная доля этой причины в старых 15 отказах НЕ установлена — журнал не содержал статусов генерации по каждому кейсу. | Бounded recovery: только при фактически усечённом *read-only* MCQ допускается **одна** повторная JSON-schema генерация; никакого доступа к ключам, тестовому ответу, бирже и торговым командам. Полный невалидный вывод не «отмывается» повтором, а отклоняется. Пишутся агрегируемые метки `finish_reason` и `fallback_used`. |
| P1 | **Слабая точность поиска источников:** отдельный безмодельный аудит [43229277968](https://github.com/19wolfalone92/Williams-AI/actions/runs/43229277968) получил совпадение целевого rule_id в top-2 лишь **23/32**: TC1 4/8, NTD 8/8, TC2 6/8, COURSE 5/8. Это диагностические, давно известные примеры, не новая blind-выборка. | Добавлен сохранённый forensic report и проверки изоляции профилей. Изменять retrieval-ранжирование по результатам прежнего теста до создания нового независимого holdout нельзя: возникнет подгонка. |
| P1 | **CI был красным из-за отсутствия cryptography**, хотя основной код мог быть корректен. | Зависимость установлена во всех трёх relevant CI-сценариях: read-only, research/DEMO, cognitive compatibility. |
| P1 | **Успех GitHub Actions ошибочно воспринимался как успех модели:** CPU exam мог завершиться успешно при 1/16 с источниками. | Отдельный `research_quality_gate`: ограничение по качеству источников, abstentions, 28-case, отдельные регрессии TC1/NTD/TC2/COURSE. Failure gate исключает продвижение, но сам факт успешно выполненного диагностического теста не скрывает. |
| P1 | Поле `weights_trained_in_this_run=true` в CPU экзамене смешивало восстановление LoRA с новым обучением. | Отдельно фиксируются `previously_gpu_trained_lora_loaded_for_inference` и `new_GPU_training_steps_in_this_run=0`. |
| P1 | Некорректный JSON (дубликаты ключей, недопустимые значения) мог проходить через нестрогий парсер. | Применён строгий JSON-парсер; запрет дополнительных полей, ограничение длины rationale 180 символами, невалидный ответ → fail closed. |

## 3. Проверенные инварианты безопасности

- Только **read-only** исследовательский контур; у экзаменатора нет доступа к API-ключам исполнения, ордерам, счетам или SL.
- Никакие задания 28-кейсного теста, ответные буквы или эталонные решения не поступают в GPU SFT.
- Независимо от `research_quality_gate`, `execution_allowed=false`, `trading_qualification=false`, `user_model_automatically_promoted=false`.
- Весовые файлы сохраняются только в зашифрованном артефакте. Не экспортировать оригиналы книг, OCR, memory/user secrets в GitHub.
- Изменения живут только в `research/williams-ai-curriculum-v5-20261111`; PR #81 не сливать в `main` до проверки quality gate и независимых экспертов.

## 4. Испытания и ограничения

1. Повторный запуск стандартных read-only, research/DEMO safety и cognitive compatibility tests по связанным коммитам; исправлять любые CI-регрессии немедленно, не скрывать ошибки заменой assertions.
2. Восстановление уже обученной LoRA, конверсия GGUF, одинаковые базовые веса для base и v5; без новых GPU циклов. Новый CPU прогон стартовал в [43229923254](https://github.com/19wolfalone92/Williams-AI/actions/runs/43229923254).
3. Старые 16 задач уже неоднократно использованы в разработке, их нельзя выдавать за новый untouched holdout. Старые показатели checkpoint500 получены с другим контрактом inference, **нельзя** делать прямую причинную оценку весов на основании одной таблицы.
4. Настоящие волны Elliott / AO / AC / фракталы / WM1-WM3 на визуальных сканах книг, реальных OHLCV, orderbook и 15-парном walk-forward НЕ подтверждены текущими MCQ. Потребуется новый набор экспертно размеченных, исторически честных графиков и строгие меры anti-lookahead.
5. 100% или 99% фактической торговой точности и прибыльности не доказаны. Потеря депозита на реальных Futures остаётся возможной — запрет реальной торговли сохраняется.

## 5. Статус завершения

**Исправлено в коде:** prompt leakage, train/inference-shape mismatch, ограниченное восстановление усечённого экзамена, строгая JSON-проверка, failure taxonomy, independent research quality gate, неверная метка обучения, CI dependency. **Получен измеренный диагноз RAG** (23/32 top-2 rule recall).

**Ожидается результат:** новый CPU экзамен после изменения декодера. Только этот запуск сможет подтвердить/опровергнуть устранение провала 1/16 с источниками; до его завершения улучшение реального Qwen после этих исправлений **не заявлять**.

**Не выполнено:** самостоятельное повторное GPU-обучение, утверждение реальной торговой квалификации, перенос в main, полноценный экспертный аудит всех графиков и всех оригинальных страниц книг.
