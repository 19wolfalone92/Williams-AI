## ✅ Основная инференция завершена и независимо проверена

[GitHub Actions **SUCCESS** #43658377350](https://github.com/19wolfalone92/Williams-AI/actions/runs/43658377350) выполнил и fail-closed проверил [полный artifact 14138759783](https://github.com/19wolfalone92/Williams-AI/actions/runs/43658377350/artifacts/14138759783): `complete=true`, **100 реальных Base-ответов и 100 ответов подлинной обученной v5 LoRA**, без экспертных меток и без биржевых ордеров.

Сверено по первичной [проверенной архивной выборке Binance](https://github.com/19wolfalone92/Williams-AI/actions/runs/43588356736): **25 инструментов × 4 исторических среза, 1024 закрытых H1 на график = 102 400 исторических баров; 200 официальных ZIP/.CHECKSUM SHA256**. 2400 будущих H1 баров были изолированы и моделям не передавались. Каждая из **200 выходных строк** сопоставлена с исходным case ID, символом, датой, книгой и **исходным chart_sha256**. Внутри каждой Base/LoRA пары проверены идентичные входные SHA промпта. Зафиксирован исходный SHA обученного адаптера `8bd26590df627c7452d56e81df6a4572885bfc82515259a7c9de4a3970c850b8`.

Вычисление осуществлялось **на NVIDIA T4** в приватном Kaggle, HuggingFace/PEFT/NF4 (Qwen3-4B Base против той же модели + реальная v5 LoRA с 80 шагами оптимизатора). [98 пар](https://github.com/19wolfalone92/Williams-AI/actions/runs/43658053110/artifacts/14138509043) независимо извлечены из остановившегося GPU run, ещё **2 недостающие пары** (`HIST100-25-3`, `HIST100-25-4`) вычислены реально в отдельном приватном Kaggle kernel. Сводный GitHub job принял **100 уникальных пар** только после реальных расчётов.

**Значимое ограничение:** первые 98 GPU prompt ограничены максимум 3200 входными токенами, две последние используют fallback до 4096; это неоднородный token-budget. CPU GGUF/llama.cpp и GPU HF/NF4 также используют разные механизмы декодирования/длину контекста. Не смешивать статистику этих backend как одну метрику.

## 📊 Реальные результаты GPU на 100 графиках

| Показатель | Qwen3-4B Base | Обученная v5 LoRA |
|---|---:|---:|
| Реальные модельные строки | **100** | **100** |
| `finish_reason=stop` — корректная выдача | **43** | **66** |
| `finish_reason=error` — техническая ошибка | 57 | 24 |
| `finish_reason=length` — обрезанный ответ | 0 | 10 |
| `ABSTAIN` (включая технические отказы) | 87 | 62 |
| `INSUFFICIENT_DATA` | 13 | 25 |
| `WAVE_HYPOTHESIS` | 0 | 13 |

**Base и LoRA выбрали разные категории в 47 из 100 случаев.** 47% — **НЕ точность**. Главный обоснованный эффект обучения в этом эксперименте — рост доли корректно завершённых ответов **43% → 66%** (техническая метрика). При этом **34% ответов LoRA всё ещё ошибочны по формату/обрезаны**. Считать `ABSTAIN` после `error/length` осмысленным решением запрещено: 57/87 у Base и 34/62 у LoRA — технические, а не содержательные воздержания.

На TC2 25/25 LoRA сказала «недостаточно данных», что может быть правильно при отсутствии биржевого статуса, но экспертного эталона нет. На Course Base 25/25 нарушает формат декодирования.

## 🖥️ Независимый CPU-контроль GGUF/llama.cpp — не завершён

[Actions #43639364206](https://github.com/19wolfalone92/Williams-AI/actions/runs/43639364206) продолжает проверку **10 отдельных 10+10 шардов**. Подтверждены завершённые шарды 0, 1, 2: **30/100 графиков, 60 реальных CPU ответов**. Base против LoRA различаются в **7/30** кейсов. В 30 общих исходных ID при сравнении CPU с GPU совпали выбранные категории: Base **12/30**, LoRA **25/30**. Это не процент правильности — backend и промпты разные. Остальные CPU шарды требуют терминальной проверки.

## 🔎 Найденные причины и исправления

1. Монолитный CPU run был отменён при лимите **355 минут**; заменён на 10 независимых шардов, агрегатор не принимает недостающие ответы.
2. Первое исполнение GPU: исправлен путь к вложенному приватному адаптеру; SHA подлинного обученного LoRA строго сверяется.
3. Второе исполнение GPU: устранён CUDA SDPA `OutOfMemoryError` (запрос ~6.96 GiB при 3.64 GiB свободно на T4) путём ограниченного входного контекста.
4. Третье исполнение GPU: 98 пар были получены, 99-я не влезала в 3200 токенов при 20 H1. Частичный результат **сохранён отдельно с `complete=false`**, затем два остаточных случая реально досчитаны с явно оговоренным 4096-token fallback. Слияние выполнено только при проверке полных 100+100.
5. **Не устранено:** высокая частота технических ошибок JSON-декодера, особенно на NTD/COURSE. Исправление требует **отдельной** версии протокола и новых контролируемых экзаменационных случаев; подменять уже сохранённые ответы нельзя.

## ❗ Научная оценка

**НЕТ независимой экспертной разметки** сигналов по TC1/NTD/TC2/Profitunity Course на этих 100 графиках. Поэтому **правильность методологии Билла Вильямса в процентах НЕ ОПРЕДЕЛЕНА**, нельзя заключать о 95–99% соответствии, прибыльности или торговой квалификации. Четыре коррелированных рыночных даты не равны 100 статистически независимым будущим торговым ситуациям. Предстоит экспертный экзамен с доказательными правилами, затем перспективный H1 holdout, исследование неточностей и проверка брокерского Demo/SL в отдельном Williams Bot.

**Безопасность и изоляция:** `main` не изменён, Williams Bot не менялся, реальных биржевых ордеров/запросов на торговлю не было.
