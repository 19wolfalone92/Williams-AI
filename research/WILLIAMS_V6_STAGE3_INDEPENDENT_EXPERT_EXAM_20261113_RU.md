# Williams AI v6 — Этап 3: независимый экспертный экзамен (протокол и готовность)

**Дата:** 13 ноября 2026. **Статус:** инструментальный протокол реализован, независимая экспертная выборка **ещё не получена**. Это не результат экзамена модели.

## Почему нельзя снова учить на 28 задачах

Последний [CPU-экзамен #43229923254](https://github.com/19wolfalone92/Williams-AI/actions/runs/43229923254) использовал известные разработчикам задания и синтетические метки. Повторное редактирование ответов, повторное использование тех же case IDs или старых графиков ради улучшения процента исказит оценку. Наиболее критичный симптом — `TC2.REVERSE`: модель v5 вернула пустую распознанную букву, но сырая генерация не была сохранена; это **не доказательство** незнания правила реверса. Применение старого checkpoint500 в качестве базового контроля запрещено из-за несовпадения декодирования/RAG.

## Реально реализовано

Модуль `williams_ai/independent_exam_v6.py` (stdlib + `cryptography` только для Ed25519 в стадии проверки подписи) содержит **две независимые CPU-команды**:

1. `freeze` — проверяет пользовательские **файлы закрытых OHLCV-баров**, SHA-256 каждого графика, известную редакцию первоисточника, временную границу, уникальность снимков и стороннего происхождения, отсутствие ответов в публичном файле и разнообразие книг/задач; закрепляет неизменяемый SHA-256 датасета.
2. `grade` — допускает оценки только двух разных внесённых в доверенный список экспертов с различными **проверенными цифровыми подписями Ed25519**; отвергает несовпадение ключей, ответов, протокола декодирования, обрезанные ответы, меняющиеся графики и чужие case IDs. Разногласия экспертов не подгоняются: исключаются из подтверждённых меток и снижают покрытие.

Считать сам список доверенных подписантов или два разных ключа *доказательством компетентности людей нельзя*: реальные личности и независимость экспертов проверяют **вне программы**. Публичные метки не являются независимыми экспертными метками просто потому, что их написал AI.

Контроль сравнивает **текущую v5 LoRA и исходную Qwen3-4B** на новом, одинаковом декодировании и RAG. Границы: отдельные счётчики каждой книги, отказов, опасных избыточных сигналов, статистическая нижняя 95%-ная граница Wilson; порог 95% считается удовлетворённым только при нижней границе >=95%, отсутствии критических ложных входов, отсутствии регрессий по каждой книге и хотя бы одном дополнительном верном ответе против базы. Даже успешная исследовательская оценка **не разрешает торговлю**, GPU-тренировку или автоматическое слияние.

## Требования к действительно новой выборке

* Минимум **32 уникальных** реальных случая (не менее 8 на книгу), 8 различных дат, минимум по 4 задачи входа, выхода, волнового контекста, уникальные SHA-256 графиков, `cutoff_utc` и **только завершённые на этот момент бары**. Для серьёзной статистической оценки 95% обычно понадобится существенно больше 32 случаев (целевой набор 200+ с представлением разных рыночных режимов).
* Условия `LONG_STOP_ENTRY`, `SHORT_STOP_ENTRY`, `NO_SETUP`, `INSUFFICIENT_DATA` при входе; `EXIT_LONG`, `EXIT_SHORT`, `HOLD` при выходе; `WAVE_CONFIRMED`, `WAVE_HYPOTHESIS`, `WAVE_INVALID` для волн. Никаких автоматических биржевых ордеров.
* Люди-эксперты самостоятельно фиксируют решения, неопределённость, конкретные страницы и обоснования; оба должны иметь доступ к первоисточнику, а при споре — **не объявлять победителя голосованием AI**.
* Кандидатные графики и тестовые ответы нельзя формировать из `28 synthetic`, старого checkpoint500, размеченных 48 старых ревью-графиков без проверки пересечений или любых train/validation split. Внешняя независимость от обучения требует документального аудита; программа умеет проверить SHA и даты, но **сама не может доказать новизну содержания**.
* До появления полного доверенного набора — результат **BLOCKED: NO EXPERT LABELS, NO TRUE HELDOUT SCORE**. Не запускать GPU.

## Минимальные структуры приватного входа

`cases.json` с полями `schema,dataset_id,cases,provenance_note`. Каждый элемент `cases`: `id,edition,family,chart_file,chart_sha256,cutoff_utc,source_pdf_sha256,pdf_pages,question,provenance_id`. Публичная карточка **без** `gold/expected/correct/answer/label/decision/review/prediction`.

Локальный файл графика содержит `symbol` и `bars`; 64+ реальных баров, каждый с `open_utc,close_utc,open,high,low,close,volume`. Не публиковать приватные графики без явного разрешения.

`review_a.json` и `review_b.json` имеют `payload` и `signature_hex` (Ed25519-подпись над строго каноническим JSON `payload`). Payload: `schema,dataset_sha256,reviewer_id,labels`. Каждая запись labels: `id,decision,pages,rationale,reviewable`.

`trust.json` содержит отображение `reviewer_id -> {ed25519_public_key_hex,externally_vetted_expert,independent_of_training}`. Приватные ключи **не хранить в репозитории и не загружать в CI**.

`predictions.json` содержит `schema,dataset_sha256,protocol_sha256,models`, модели `candidate_v5` и `matched_base` с разными `weights_sha256`, одинаковым `protocol_sha256` и списком `answers` с `id,decision,finish_reason`. Не переносить исходные ответы экспертов в запросы к модели.

Запуск локально (никаких внешних подключений):

```bash
python -m williams_ai.independent_exam_v6 freeze --cases private/cases.json --chart-root private/charts --out private/frozen_manifest.json
python -m williams_ai.independent_exam_v6 grade --cases private/cases.json --chart-root private/charts --manifest private/frozen_manifest.json --review-a private/review_a.json --review-b private/review_b.json --trust private/trust.json --predictions private/predictions.json --out private/score.json
python -m unittest tests.test_williams_ai_independent_exam_v6 -v
```

## Проверка изменений

Для новых функций создан `tests/test_williams_ai_independent_exam_v6.py` — **9 негативных/позитивных локальных проверок с искусственными тестовыми графиками**, никак не оценивающих знания настоящего AI. Для независимого CI: [`ai-v6-expert-intake-cpu.yml`](../.github/workflows/ai-v6-expert-intake-cpu.yml); только CPU, без биржевых ключей и секретов. Результаты CI необходимо подтвердить отдельно.

## Граница этапа

**Реализовано:** схема данных, криптографическая проверка двух рецензентов, контроль причинности баров, агрегирование по четырём книгам, fail-closed исследовательский quality gate и CI тестирование.

**Не реализовано/не получено:** новые реальные независимо промаркированные графики, два подтверждённых эксперта, реальный запуск Qwen3-4B на этих графиках, независимая экспертная точность.

Любой отчёт о >=95% на старых разработческих вопросах не может заменить этот этап.
