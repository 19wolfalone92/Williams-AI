# Williams AI — прерываемое бесплатное QLoRA на настоящем GPU

Исследовательский модуль: `williams_ai/qlora_gpu_research.py`.

## Что он реально делает
При наличии CUDA/NVIDIA и разрешённых пользователем данных загружает **неквантованные HF safetensors Qwen**, квантует базу для вычислений NF4 4-bit и обучает только PEFT LoRA. 10 шагов оптимизатора за минимальную сессию. Контрольная точка V2 требует веса и конфигурацию адаптера, optimizer/scheduler/RNG, FP16 scaler и состояние Trainer. Манифест SHA-256 записывается после каждого полного сохранения и связывает checkpoint с исходной оценкой по четырём книгам. Следующий сеанс требует совпадения SHA-256 модели/токенизатора, исходного JSONL, точного Git SHA, версий среды, режима надзора и всех гиперпараметров.

**Запуск здесь не выполнен:** нужен настоящий CUDA GPU, подготовленный пользователем HF model directory, независимая размеченная выборка и согласованная облачная обработка. Ни одна строка здесь не запускается автоматически, не включает торговлю и не заменяет Android GGUF.

## Требования к данным
Используется существующий `checked_private_training_data` с независимыми экспертными отметками, всеми четырьмя книгами и отдельными train/validation/test. Для рыночного обучения `require_market_supervision`: OHLC только видимых на момент решения свечей, без утечки будущего, несколько разных форм рыночной структуры, разметка риска/сигналов/альтернатив. Автоматически созданные Qwen-метки не считаются истиной. Тексты книг не помещаются в GitHub, Kaggle должен иметь приватное разрешённое хранилище.

## Команда на приватной Kaggle/CUDA-машине
Перед исполнением установить подходящие CUDA PyTorch, `transformers`, `peft`, `accelerate`, `bitsandbytes`, `safetensors` и проверить совместимость версий. Для прямого запуска задать `CUDA_VISIBLE_DEVICES=0`: используется ровно один видимый GPU. Код должен быть чистым checkout указанного Git SHA. CI запускает реальные шаги оптимизатора на **случайной крохотной Qwen3 и искусственных токенах CPU FP32**; это проверка программы, не обучение торговой Qwen.

```bash
python -m williams_ai.qlora_gpu_research \
 --reviewed-jsonl /kaggle/input/private-reviewed/reviewed.jsonl \
 --hf-base /kaggle/input/private-qwen-hf \
 --new-output /kaggle/working/session-001 \
 --source-revision <PINNED_GITHUB_COMMIT_SHA> \
 --max-steps 200 --session-steps 10 --max-tokens 1024 --rank 8 \
 --source-only-research --authorize-cloud-data-processing
```

`--source-only-research` явно означает обучение ПО ИСТОЧНИКАМ, а не сертификацию анализа рынка. Для рыночного обучения убрать флаг и предоставить проверенную рыночную разметку.

Следующий сеанс получает новое `--new-output` и `--resume-directory /kaggle/input/own-checkpoints/session --trusted-own-resume`. Последняя запечатанная полная точка выбирается автоматически; незапечатанный незавершённый каталог игнорируется. Также поддерживаются явные `--resume-checkpoint .../checkpoint-10 --resume-receipt .../contract.json`. В каталоге рядом с `contract.json` должен находиться `checkpoint_sha256.json`. Исходный baseline сохраняется при каждом продолжении и сравнивается с итоговой оценкой всех четырёх источников. Старые V1 receipts без весов/scaler/baseline не принимаются. **PyTorch optimizer.pt потенциально опасно распаковывать из чужих источников; SHA-256 не удостоверяет автора.** Облако Kaggle может не сохранить выход при аварии: экспорт собственных checkpoint остаётся ответственностью оператора.

`latest_adapter/` — последние веса для исследования, а не автоматически выбранная лучшая или разрешённая к торговле модель. Сохранённый полный checkpoint продолжает последнюю траекторию оптимизатора. Приёмка качества и слепой test holdout остаются отдельными этапами.

## Фактическая проверка восстановления
`python scripts/ai_qlora_resume_diagnostic.py` сравнивает непрерывные 20 шагов с 10+10 шагами в отдельных новых процессах. Проверяются остановка внутри эпохи на 32 примерах и граница эпохи с неполным накоплением градиентов на 35 примерах; накопление — 8. В обоих сценариях локально получены **нулевые различия всех весов адаптера и logits после загрузки**. Замороженная база не меняется; нечисловой baseline останавливает обучение до optimizer step. Ошибка сброса эпохи sampler при `Accelerate.skip_first_batches` исправлена порядком данных, выводимым из восстановленного прогресса оптимизатора. Веса и финансовые знания настоящей Qwen этим тестом не обучаются.

## Незавершённые обязательные проверки
GPU OOM/точная совместимость Qwen/PEFT, восстановление реальной GPU-сессии, корректность ответов и исходных рисунков всех 4 книг, независимый holdout, калибровка UP/DOWN/RANGE, результаты реальных торговых кампаний с комиссиями и проскальзыванием, проверки Android/GGUF и Demo SL recovery. Не считать пройденную CI-проверку доказательством торгового качества.
