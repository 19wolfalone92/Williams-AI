## Проверенные ограничения кода

1. `market_decision_curriculum._waves`: `wave_confirmed=False` и `squat_verified=False` для всех сгенерированных примеров. Новая аудиторская CI-проверка подтверждает отсутствие положительных примеров на train, validation и test.
2. `_waves_at`: проверка двух готовых альтернатив A/B вместо самостоятельного поиска разметки; нет независимого экспертного подтверждения.
3. `_campaign_at`: условные `fills`, `stop_ack`, `trail_review`; не журнал фактических ордеров.
4. `contrastive_book_practice.tokenize_typed`: супервизия по готовым JSON и повышенная важность токенов значений; не является доказательством качественного объяснения.
5. `serial_50_engine.Rows`: циклическая смена пяти пулов по номеру шага вместо обучения по классифицированным ошибкам предыдущего шага.
6. `joint_rule_curriculum.selection`: метрика выбора чекпоинта косвенная и не использует прямой штраф за риск.
7. `ai_verify_serial_50._observed_safety`: отдельный счётчик `wrong_ac_direction` считает только явные LONG/SHORT; нулевой результат сам по себе не доказывает безошибочность AC.
8. Проверенный тест: direct decoding, до 192 новых токенов и 25 секунд на ответ. Сложное объяснение и самостоятельное формирование гипотез остаются вне покрытия этого экзамена.

## Реализованные исследовательские компоненты (PR #75)

- `scripts/ai_audit_training_v2.py`: чтение **реальных замороженных кейсов** генератора, проверка дублирования межгрупповых примеров, распределения ответов и коллапса меток; отчёт публикуется только как CI-артефакт без закрытых PDF и секретов.
- `williams_ai/reasoning_research_v2.py`: строгий формат экспертно проверенных книжных/рыночных примеров; SHA источника, закрытые последовательные OHLCV данные, положительные и отрицательные обоснования, подготовка train-only SFT, валидационные/тестовые **вопросы без ответов**, частная SQLite-память гипотез; выбор тренировочных вопросов по **кодам ошибок**, но не по ответам held-out.
- `williams_ai/reasoning_walkforward_v2.py`: последовательная историческая проверка с доступом только к закрытому префиксу и уже записанным гипотезам, а затем — отдельная оценка по скрытому gold.
- `scripts/ai_reasoning_v2_lab.py`: приватный CLI `prepare`, `schedule`, `compare`.
- Тесты и CPU CI: проверяют границы train/validation/test, отсутствие будущих свечей, происхождение правил, невозможность самостоятельной «сертификации» результатов и запрет исполнения.

## Шесть этапов и текущие ограничения

| Этап | Что реально сделано | Что не сделано |
| --- | --- | --- |
| 1. Аудит | Исходники ключевого обучения, реальные 360 тестов, GPU-журнал, независимый результат, генератор замороженных данных и CI проверены | Нет расшифрованного оригинального LoRA и повторного инференса каждой ошибки |
| 2. Учебные материалы | Реализован новый строгий формат с двойной проверкой, без синтетических «положительных волн» | Нет достаточного корпуса новых независимых экспертных меток |
| 3. Память | Добавлен приватный причинный журнал гипотез | Не интегрирован с Android и реальным Qwen runtime |
| 4. Адаптация | Подбор train-задач по категориям ошибок validation без утечки test | Не проведено новое дообучение весов |
| 5. GPU | Выявлены параметры, слабые результаты и условия допуска нового эксперимента | Новый QLoRA эксперимент **не запускался**: нет проверенной экспертной обучающей выборки |
| 6. Экзамен | Добавлены последовательный replay, контроль закрытых свечей и парное сравнение | Реальные веса parent/candidate не прогнаны по новому экспертному экзамену |

**Следующая ключевая зависимость:** приватные примеры, действительно проверенные по исходным книгам и реальным графикам двумя экспертами. Декларации reviewer_id проверяют структуру согласования, но не удостоверяют личность и квалификацию людей. Нельзя честно «создать» профессиональную экспертную разметку из собственных гипотез модели.

**Запрет:** никакой live торговли, автоматического продвижения весов или передачи закрытых книг/ключей в репозиторий.
