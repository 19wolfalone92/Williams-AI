# Williams AI 5.0 — обучение заново с проверяемым качеством
**Дата подготовки: 2026-11-11. Состояние: подготовка и эксперимент, не авторизация торговли.**

## 1. Диагноз по фактически завершённым экзаменам

- Публичная Qwen3-4B: закрытая книга 6/16; автоматически поданные карточки 2/16.
- Оригинальная Williams Qwen3-4B + 50 циклов QLoRA (1000 шагов, checkpoint-500): закрытая книга 9/16, карточки 8/16.
- У обученного кандидата *без* карточек два abstention/malformed, *с* карточками **семь**. Пять случаев испорчены дополнительным контекстом, четыре исправлены.
- Предыдущий 360-кейсный замороженный тест: 110/360 → 115/360, но 21 регрессия, AC 54/72→50/72, риск oversize 15→16, исследовательский gate=false.
- **Следовательно, нельзя считать, что 50 повторений сами по себе научили модель правильной рыночной логике.** Частые отказы на 16 MCQ могут быть обусловлены формированием JSON и недостаточным бюджетом вывода thinking-mode, а не ошибкой книжного знания. Отдельно проверить без-thinking JSON и достаточность генерации до ещё одного большого обучения.

## 2. Что меняем в методике

### Базовая архитектура
1. **Qwen3-4B как языковое ядро** (официальный исходный коммит, проверяемые safetensors).
2. **Source-grounded RAG** — проверенный книжный текст и отметка конкретной страницы, НЕ знание автоматически сохранённое в весах. Course OCR/сложные графики остаются без статуса экспертной разметки до независимой проверки.
3. **Небольшой QLoRA SFT** — обучает форму ответа, явное разделение TC1/NTD/TC2/Course, ссылки на страницы, ограничения и поведение при недостаточности данных. Не использовать неподтверждённые прогностические сигналы в train.
4. **Последовательное рассуждение** — факты рынка (инструменты) → гипотеза → контргипотеза → первоисточник → решение WAIT/RESEARCH. Изображения обрабатывает отдельная модель зрительного понимания, но не выдаёт собственный вывод за expert gold.
5. **Память ошибок** — только проверенные по времени, модели и источнику уроки; никогда не повторять опубликованные тестовые ключи в train.
6. **Независимый экзамен и rollback** — сравнить base vs serial50 vs v5 по одинаковому протоколу и на новых unseen задачах; дополнительный риск/AC/TC2 gate и отсутствие критических регрессий.

### Почему меньше обучения, а не ещё 50 циклов
Повторение некачественной разметки усиливает её ошибки. Пока нет независимых экспертных положительных меток wave/Squat и проверенных воспоминаний по реальному рынку, 50 циклов выглядят как способ переобучить модель на шаблоны и испортить ответы.
Начинаем с 80–120 шагов QLoRA, сохраняем и выбираем лучший checkpoint **только по validation**, и запускаем test ровно после выбора.

## 3. Реальная учебная база v5

Модуль: `williams_ai/knowledge_curriculum_v5.py`.

- Источники: **37 закреплённых карточек** к четырём книгам с исходными SHA256 PDF и PDF-страницами. Исключена диаграмма `COURSE.VISUAL.NESTED_ABC`, пока её разметка не сертифицирована независимым экспертом.
- Используется **36** карточек → **12 проверяемых учебных упражнений на карточку**.
- Разделение выполняется по **целому rule_id**, а не по тексту одного запроса: одна книжная карточка может относиться только к ОДНОМУ train/validation/test. Каждое из 4 изданий присутствует во всех трёх разделах.
- Форматы: MCQ с перемешанной позицией правильного ответа, структурированное объяснение `KNOWLEDGE` с ссылкой на исходную страницу, безопасный `BOUNDARY` при отсутствии подтверждённых рыночных фактов.
- Источники — **публичные пересказы ранее проверенных страниц**, не полный текст PDF, не OCR, не изображение, не реальные биржевые операции.
- Пустые бумажные формы и непроверенные геометрические рисунки не превращаются в экспертные эталоны. У всех примеров `chart_expert_gold=false` и `execution_allowed=false`.
- Формат: SQLite `rules / curriculum / manifest`, строгие `case_id`, хэши train/dev/test вопросов и ответов; воспроизводимый seed; JSONL можно генерировать из SQLite при необходимости. Физический файл базы собирается в GitHub Actions и прилагается к workflow.
- **Новая база не доказывает обучение смыслу рисунков**, но даёт контролируемый SFT-эксперимент по книжной терминологии, грамматике ответа и отказу от выдуманных рыночных подтверждений.

## 4. Этапы эксперимента и критерии

| Этап | Выполнение | Строгая проверка |
|---|---|---|
| A. Проверка источников | SHA книжных карточек, отделение визуальной разметки, подсчёты 4 книг | 36 карточек, каждая в одном split |
| B. Пробная база | 12 форм/карточку → защищённый SQLite | нет дублей, future/test leakage, нет оригиналов PDF |
| C. CPU preflight | юнит- и регрессионные тесты; контроль токенизации | модель получает **только train**, validation лишь loss |
| D. Настоящий GPU | NF4 double-quant + Qwen3-4B + LoRA rank 8, LR 5e-5, 80–120 шагов, answer-only loss | реальные изменения LoRA весов, frozen official HF commit |
| E. Выбор checkpoint | Сравнение loss validation по TC1/NTD/TC2/Course | test ключи запрещены для подбора |
| F. Реальный экзамен | Исходная 16/32-книга, плюс НЕИЗВЕСТНЫЙ rule-disjoint holdout и TC2/AC/риск | сравнение base/serial50/v5 на одном протоколе |
| G. Промоушен | только после нового независимого экспертного chart walk-forward | сейчас запрещён, `execution_allowed=false` |

## 5. Что ещё необходимо для действительно глубокого обучения

1. Проверить 68 иллюстрированных страниц Course, затем добавить одобренные **схемы координатами** (стрелки, волновые степени, геометрические отношения), но не галлюцинации vision-LLM.
2. Создать минимум по два **независимо проверенных** примера положительного/отрицательного wave и Squat в каждом Train/Dev/Test сегменте; market timestamp + model version + case digest + source.
3. Исправить response schema и устойчивость retrieval отдельно от SGD; сравнить thinking/off и бюджет токенов, иначе обучение может маскировать сбой декодера.
4. Автоматически собирать настоящие исправленные ошибки и проверять противодействие забыванию старых правил на per-book тесте.
5. Пользовательские торговые результаты не должны использоваться как мгновенный reward без комиссии, slippage, ликвидности, закрытых свечей и walk-forward.

## 6. Границы достоверности

- **CPU тест ≠ настоящее дообучение 4B.** Только GPU workflow со статусом COMPLETE, подтверждённой контрольной суммой adapter и проведённым новым экзаменом позволяет утверждать, что новая модель обучена и проверена.
- **Loss/MCQ ≠ прибыльность и понимание волн.** Для допуска к реальной торговле нужны отдельные рыночные тесты, негативные и стрессовые сценарии, проверка SL/ исполнения и работы Android.
- Нет права публиковать пользовательские оригиналы книг и приватные веса; private Kaggle job, либо ограниченный набор публичных парафраз — не сами PDF.

Источники методик: Qwen3 официальный режим thinking/non-thinking [huggingface.co/Qwen/Qwen3-4B](https://huggingface.co/Qwen/Qwen3-4B); HF TRL PEFT [PEFT integration](https://huggingface.co/docs/trl/peft_integration); официальные рекомендации [QwenLM/Qwen3](https://github.com/QwenLM/Qwen3).
