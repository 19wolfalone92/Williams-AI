# Williams AI — эксперимент 50 последовательных мини-обучений

## Что действительно выполняется

**50 последовательных мини-циклов по 20 попыток обновления оптимизатора, всего до 1000 попыток в одной Kaggle GPU-сессии.** Это **НЕ** 50 отдельных двухчасовых полных GPU-обучений, которые потребовали бы порядка 100–130 часов и превысили бы подтверждённую бесплатную квоту Kaggle. Общее время и сумма обновлений ограничены заранее.

В отличие от просто записи «50» в отчёте, каждому циклу соответствует фиксированная последовательность из 20 шагов, реальный счётчик обновлений LoRA и запись о его завершении. В конце независимый CPU-верификатор проверяет наличие **всех 50** записей с действительным прогрессом весов. Если хотя бы одна мини-фаза не состоялась, обучение **не объявляется завершённым**.

## Техническая модель

- Отправная точка: только защищённый проверенный выход V2 от 10.11.2026, SHA256 `2a18d0b3788c10bc851a155ee89c2997e08bf63b00fa6e6d345e676e5960ec9a`, исходный GitHub SHA `e427de188591136cbc022c4c26ae332a77fac8f3`. Он **не является** допущенным к торговле чемпионом.
- Qwen3-4B, pinned base model revision, 2×Tesla T4, QLoRA NF4 4-bit, LoRA rank 16, alpha 32, FP16 AMP; только 33,030,144 матрицы LoRA обучаемы.
- 50 мини-циклов по 20 шагов с общим состоянием LoRA и **непрерывным состоянием оптимизатора**. Перемена учебного акцента через каждые 20 шагов; пять групп повторяются десять раз: **risk/AC → context → waves → TC2/campaign → books**, с периодической подмешанной книжной и риск-практикой в каждом цикле.
- `optimizer_attempts:1000`, `evaluation_steps:250`, `learning_rate:2e-6`, `source_repetitions:3`; время GPU обучения до 10800 с, верхняя граница Kaggle 18000 с; однократная контролируемая отправка в Kaggle.
- Самообучение на выходах модели **отсутствует**: только детерминированные учебные эталоны / известные оригинальные книги. Числовые примеры не являются экспертно размеченными графиками.
- Пользовательский STOP: `experiments/serial-50-control.json`, поле `stop:true`, fail-closed при потере связи. Если Kaggle не подтверждает бесплатную квоту, родительский checkpoint, приватный источник или уникальный slug, **запуск не делается**.
- Все учебные промпты: `execution_allowed=false`. Ни реальных, ни demo-приказов. Никакого изменения Williams Bot.

## Научная проверка улучшения

- **Перед началом** зафиксированы train/validation/test и SHA256 их контента, отдельные 32 ранее не использованные расчётные задачи (16 risk + 16 AC). Старые 2026 рыночные графики и уже раскрытые тесты V1/V2 — **не новые слепые экзамены**, а регрессии.
- Валидируется только `validation` (каждые 250 попыток), выбирается лучший валидированный checkpoint, потом **один раз** загружаются финальные test-вопросы без ответов. Предыдущая V2 модель и новый кандидат отвечают на те же вопросы.
- CPU независимо пересчитывает эталоны, версии модели, веса LoRA, 50 достоверных циклов, 4 cohort gates (`context/waves/campaign/precision`), исполнение STOP, неправомерные разрешения ордеров, превышения risk_budget, неверные направления AC и ошибки кампаний. Проверяет source validation по четырём книгам, чтобы не допустить забывание методики.
- **Квалификация не гарантирована**. Даже если точность растёт, безопасность требует нулевых опасных ошибок, а самостоятельная рыночная проверка с комиссиями, проскальзыванием и no-lookahead ещё не выполнена. Результат всегда research, не продвигается в `main` автоматически.

## Артефакты

Архив финальных LoRA-весов шифруется X25519 + AES-GCM перед отправкой в GitHub Actions. Отдельно доступен открытый независимый CPU-аудит и доказательство всех 50 фаз; один GitHub зелёный статус сам по себе не означает успех эксперимента. Ветку/PR не сливать автоматически. Не запускать новый цикл, если уже есть активный kernel.

Запуск через единственный контрольный файл `experiments/serial-50-start.json`; dry-run проверяется отдельно. Отчёт обязан различать *50 мини-циклов* и *50 полных GPU-сессий*.
