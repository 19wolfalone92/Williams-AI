# Williams AI: фактическая приёмка механизма LoRA recovery

Работа только в `19wolfalone92/Williams-AI`, ветка `fix/qlora-resume-integrity-20261026`, база `302724d6143d0b5e29d9bd2829dcbbe3c2424ea4`. Williams Bot 2.1 / `19wolfalone92/Williams` не изменён.

## Воспроизведённые ошибки

1. Предыдущий seal принимал optimizer/scheduler/RNG без сохранённых весов адаптера, конфигурации и FP16 scaler. Такой каталог не подтверждал полное восстановление.
2. После первого сеанса терялся исходный четырёхкнижный baseline; следующий отчёт не сравнивал адаптер с исходной базой.
3. Контракт не связывал checkpoint с версиями ML-среды и режимом исходного надзора; разрешался неполный Git SHA.
4. Прерванный фиксированный временный файл манифеста блокировал следующие сохранения.
5. Настоящий тест 20 против 10+10 шагов сначала **провалился**: максимальное различие весов составило `0.0006086081266403198`. Checkpoint-10, RNG и optimizer были одинаковы; расхождение возникало после продолжения. Accelerate 1.10.1 создаёт новый shard при пропуске batch и сбрасывает его iteration, меняя порядок примеров внутри восстановленной эпохи. Исправление использует номер эпохи из восстановленного `global_step`, сохраняя перемешивание, dropout и накопление градиентов.

## Что изменено

- Контракт/receipt/seal V2: полный состав checkpoint, SHA исходного baseline, строгий JSON, одинаковая среда и режим обучения. Старые неполные V1 checkpoints отклоняются явно.
- Общий реальный Trainer-путь для GPU NF4 и синтетической CPU-диагностики; проверки конечных gradients, loss, весов и фактического изменения LoRA в каждой сессии.
- Исходный baseline сохраняется до первого optimizer step и переносится через все продолжения. Каждая финальная оценка включает ALL/TC1/NTD/TC2/COURSE. Test labels не передаются в fit.
- Последняя полная контрольная точка выбирается из seal, незавершённые незапечатанные записи пропускаются, изменённые запечатанные записи вызывают ошибку.
- Kaggle bridge принимает собственный приватный output предыдущей сессии, фиксирует тот же код и использует один GPU. Следующий запуск остаётся ручным.
- CPU workflow выполняет настоящий тест восстановления и публикует только метрики; искусственные веса уничтожаются.

## Что эта работа НЕ подтверждает

Не запускалось настоящее CUDA/NF4 обучение Qwen1.7B/4B, не проверены FP16 scaler на GPU и VRAM/Kaggle restart. Ни одна независимо проверенная новая метка не выдумывалась; оригиналы книг и приватные данные не загружались. Не обучены торговые знания и не доказаны понимание четырёх книг, калибровка рыночных вероятностей, прибыльность, применимость адаптера в Android или Binance исполнение. Автоматического включения новой модели нет.

Для фактического GPU-опыта всё ещё нужны подключённый личный GPU/Kaggle, разрешённые HF safetensors и проверенный JSONL. Подготовленный запуск не заменяет эти входы.
