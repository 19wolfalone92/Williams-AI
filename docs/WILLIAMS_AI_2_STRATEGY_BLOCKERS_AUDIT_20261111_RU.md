# Williams AI 2.0 — независимый аудит блокеров стратегии обучения (11.11.2026)

**Цель:** не оценить красоту документации, а воспроизвести препятствия для новой схемы: подтверждённые книжные и рыночные рассуждения → экспертная оценка → адаптация к ошибкам → QLoRA → независимый последовательный экзамен.

**Объект:** `19wolfalone92/Williams-AI`, ветка `research/learning-audit-remediation-20261111`, PR #75. Исходный GPU эксперимент: [Actions 42882670406](https://github.com/19wolfalone92/Williams-AI/actions/runs/42882670406). Автоматический аудит: `scripts/ai_audit_strategy_blockers.py`; [CI 42963732651](https://github.com/19wolfalone92/Williams-AI/actions/runs/42963732651). **Все семь нижеуказанных дефектов воспроизведены (`reproduced_count=7/7`) на настоящих функциях репозитория**, без GPU и торговых ключей. Результат CI `success` означает успешное воспроизведение НЕИСПРАВЛЕННЫХ недостатков, а не успешное обучение.

## P0 — воспроизведённые блокеры

### A1. Контрольная сумма корпуса не фиксирует его содержимое

**Код:** `williams_ai/reasoning_research_v2.py::check_corpus`: `source_sha256 = digest([row["case_id"] for row in cases])`. При изменении **текста вопроса** и повторном одобрении ровно того же case_id значение SHA-256 в отчёте не меняется. **Доказано CPU-пробой `CORPUS_HASH_NOT_CONTENT_BOUND`.**

**Последствия:** нельзя надёжно привязать эксперимент, контрольные выборки и результат к неизменному набору ответов/меток. **Исправить:** фиксировать канонические SHA полного корпуса (включая ответы, cutoff, market prefix, source, review) и отдельные prompt-only/test-gold digests; проверять перед каждой загрузкой и в артефакте эксперимента.

### A2. «Слепой экзамен» даёт 100% за ответ без рассуждения

**Код:** `grade_blind` из `reasoning_research_v2.py` сравнивает прежде всего `answer.decision`, но не требует `_valid_answer` у прогнозов. **Проба `BLIND_GRADER_ACCEPTS_NO_REASONING`**: `{"decision":"WAIT","execution_allowed":false}` без объяснения и контраргументов получил **100% decision accuracy и 0 unsafe claims** на проверочном кейсе WAIT.

**Последствия:** главный KPI новой архитектуры может быть пройден системой, которая не думает. **Исправить:** проверять полную схему прогнозов; оценивать гипотезы, альтернативы, инвалидацию, локальные факты, цитаты, abstention и калибровку; считать macro по правилам, классу действий и рыночным режимам, а не только decision match. Независимая экспертная оценка объяснений обязательна.

### A3. Новые SFT-уроки технически несовместимы с текущим QLoRA

**Код:** `export_research` выдаёт `train_sft` с полями `case_id,rule_id,messages`. Действующий `private_lora.checked_private_training_data` требует `case_id,edition,rule_id,pdf_page,source_sha256,question,answer,review_status,reviewer_id,split` (+ поля двойной проверки графика).

**Проба `NEW_SFT_INCOMPATIBLE_WITH_EXISTING_QLORA`** подтверждена. В PR #75 нет изменений `serial_50_engine.py`, `private_lora.py`, `qlora_gpu_research.py` или `scripts/ai_run_serial_50_kaggle.py`, подключающих новый контракт.

**Последствия:** запуск новых фрагментов ещё **не обучает ни одного параметра Qwen**. **Исправить:** один проверяемый train-data adapter в новую QLoRA entrypoint, проверка токенизации и gradient smoke, затем короткая GPU training smoke; запрещать старый протокол, если выбран режим reasoning-v2.

### A4. Адаптивный курс логически обнуляет обратную связь

**Код:** `readiness` запрещает пересечение `(edition,rule_id)` между train/validation/test. Однако `adaptive_schedule` повышает приоритет только для **точно такого же rule_id**, присутствующего среди train-уроков, если обнаружена ошибка в validation. При раздельных правилах такой ошибки по одному и тому же идентификатору быть не должно. **Проба `ADAPTIVE_FEEDBACK_DROPPED_BY_RULE_SPLIT`:** ошибка NTD.AC не повлияла на подбор train-уроков; приоритет остался 0.

**Последствия:** обещанная «учёба на ошибках» не работает в допустимом разбиении. **Исправить:** две разные оценки: (а) case-disjoint по общим навыкам для адаптивной валидации, (б) полностью rule-disjoint для настоящего переноса; связывать error_code с доменным **skill taxonomy**, а не только с точным идентификатором книжного правила. Никогда не использовать test labels при обучении.

### A5. Нет защиты от утечки между котировочными алиасами

**Код:** `check_corpus` разбивает по **полной строке символа**. **Проба `QUOTE_ALIAS_LEAKAGE_NOT_BLOCKED`**: BTCUSDT(train) и BTCUSDC(test) с одной историей прошли проверку как «разные активы». Старый `chart_supervision.check_market_partitions` уже содержит более строгую логику группировки underlying + embargo и не используется здесь.

**Последствия:** одинаковое базовое движение может попасть и в train, и в тест, скрывая переобучение. **Исправить:** переиспользовать legacy группировку underlying/venue/quote alias + временной embargo и хеши окна; отдельно проверять временной holdout на *тех же* монетах для оценки способности сопровождать рынок.

### A6. Модель не получает необходимые данные для нового мышления

**Код:** `question_only` передаёт **последние восемь свечей одного TF**, рассчитанные jaw/teeth/lips/AO/AC, код правила и номер страницы. Нет H4/D1-панорамы для H1 решения, подтверждённых swing/pivot структур, полноценного книжного отрывка, происхождения рисунка или доказательств объёмного MFI. **Проба `NO_H4_D1_SWINGS_OR_BOOK_EVIDENCE_IN_PROMPT`** успешно воспроизведена.

**Последствия:** модель не в состоянии самостоятельно доказать ряд волновых, межтаймфреймовых и книжных утверждений из того, чего **нет на входе**. **Исправить:** причинные закрытые H1/H4/D1 представления, структурные pivots с confirmed_at, волновые кандидаты и опровержения, правило+разрешённая краткая цитата/график, контекст объёма с обозначением источника; ограниченный token budget и проверяемые ссылки.

### A7. Память гипотез смешивает модели и ломает парные тесты

**Код:** таблица `HypothesisMemory.hypotheses` имеет ключ `case_id`, но не имеет `model_id`, `adapter_sha256`, `run_id`, `split`, `policy_version`. **Проба `NO_MODEL_ISOLATION_IN_HYPOTHESIS_MEMORY`** подтверждает конфликт вставки второй гипотезы с тем же case_id.

**Последствия:** невозможно чисто сравнить parent и candidate с одной и той же историей или отделить учебную память от слепого экзамена. **Исправить:** составной ключ `(run_id, model_fingerprint, case_id)`, отдельно фиксируемые обучающая и экзаменационная памяти, миграции схемы, проверка идентичного исходного состояния при paired comparison.

## P0 — дополнительные подтверждённые препятствия

**B1. Отсутствует проверенный корпус экспертных рыночных меток.** `frozen_training_audit.json` из настоящего CI подтверждает: train 864, validation 224, test 360. Для всех трех выборок положительных `wave_confirmed=true` и `squat_verified=true` **нет**, а происхождение большинства рыночных ключей — машинные правила, не независимая экспертная разметка. Простые метки False не могут обучить положительное распознавание. Требуется двойная независимая проверка реальных случаев и честная метка UNKNOWN.

**B2. Новая система оценки не является фактически blind/sealed.** `run_blind_replay(test_cases, model_predict, memory)` принимает тестовые **полные** объекты с `answer`, а `model_predict` — произвольный callable в том же процессе. Функция `question_only` не передаёт answer напрямую, но не изолирует его в отдельном процессе/контейнере и не доказывает отсутствие доступа через closure. `prediction_at` может быть равен историческому cutoff без внешней аттестации времени. Для настоящего blind: отдельный сервис только с prompt-only JSONL, sealed predictions, внепроцессный оценщик gold после freeze.

**B3. Недостаточная верификация экспертных меток и покрытия книг.** В реестре всего **37** вручную проверенных кратких rule cards (TC1 14, NTD 8, TC2 8, COURSE 7), что **не эквивалентно полному содержимому 642 страниц**. Два `reviewer_id` в JSON — декларация, не удостоверение личности/независимости. Метрики не сверяют смысл каждой цитаты с первоисточником. Нужны книга-страница-рисунок-правило и независимый reviewer workflow, включая разрешение разногласий.

**B4. «Готовность к GPU» не подключена к старому запускающему коду.** `readiness()` возвращает предупреждения, а `prepare` всё равно генерирует train_sft при недостаточном корпусе. У действующих тренеров нет вызова `readiness` (PR #75 не изменяет их). Нужен fail-closed gate **в самой тренирующей функции**, а не только в самостоятельном CLI.

**B5. Оценка риска не соответствует реальной торговле.** `grade_blind` считает unsafe в основном если `execution_allowed!=false`; не контролирует entry/stop/quantity, общий риск, фрактальную защиту, execution acknowledgements и изменение волновой гипотезы. Предыдущий реальный candidate ухудшил oversize risk с 15 до 16 ошибок. Не выдавать успешный research grade за безопасность торговли.

**B6a. «Рассуждающие» обучающие примеры старой QLoRA не содержат волн и кампаний.** В `serial_50_engine.py` готовые JSON для рынков токенизируются через `tokenize_typed(... enable_thinking=False)`. Отдельные `reasoned_rows` с `<think>…</think>` выбираются **только** по `TC1.PSY.PLAN` и `NTD.AC`; для `waves` и `campaign` аналогичного подтверждённого экспертного объяснения этот путь не создаёт. Валидация через `predict_cohorts` по умолчанию использует direct-decoding. Необходимо отдельное обучение и экзамен обоснования **каждого** навыка, с проверенными объяснениями вместо неподтверждённых цепочек мыслей.

**B6. Неизмеренный перенос между чекпоинтами.** Предыдущий эксперимент сделал 1000 шагов, использован checkpoint-500; parent 110/360, candidate 115/360 (+1,39 п.п.), 26 улучшений/21 регрессия, Context 5/72, Waves 13/72, AC 54→50/72, risk oversize 15→16, все 4 gate=false. Новый pipeline пока не запускался с реальной Qwen. Новый цикл нужно запускать только после выполнения A/B, с несколькими seeds, контрольным parent, равным протоколом декодирования, абляциями и самостоятельным held-out тестом.

## P1 — риски качества, надёжности и корректности интерпретации

- **C1. Слишком слабый баланс в readiness:** достаточно по 2 true/false wave и squat в каждом split, без проверки по каждому правилу, символу, режиму и таймфрейму; минимум всего 2 TF, хотя стратегия требует H1/H4/D1. Это минимальный smoke gate, не сертификат пригодности.
- **C2. Не оценивается confidence calibration:** схема ответа имеет confidence, но `grade_blind` не рассчитывает Brier/calibration, abstention или надёжность вероятностей.
- **C3. Датасет генератора повторяет один и тот же шаблон:** в train waves 144 примера — 3 варианта первой строки, 123 случая с одинаковой основной формулировкой; в test waves 72 примера — 1 шаблон и только 23 различных готовых JSON. Это не 72 независимых творческих задания; нужно разнообразие гипотез, примеров и независимых экспертов.
- **C4. Метрики `wave_field_matches_for_non_null_gold` возвращают число совпадений без явного знаменателя; `squat_verified` не входит в итоговую оценку.** Нельзя сравнивать качество подтверждений на разных наборах.
- **C5. `adaptive_schedule` только выбирает по одному case на round и **не вызывает ни forward, ни backward, ни optimizer**; обучение по памяти и ошибкам пока лишь подготовительный контур.
- **C6. `HypothesisMemory` не получает независимых результатов напрямую, требует ручного метода `review`; нет реализации закольцованной обратной связи с QLoRA и измеримого улучшения в последующем решении.
- **C7. `scripts/ai_audit_training_v2.py` проверяет только точные дубликаты, а не похожие окна / парафразы / эквивалентные схемы задач. Показатель `duplicate_check=true` не означает отсутствия семантической утечки или переобучения.

## Порядок действий до следующего GPU запуска

1. **Сделать целостный контракт данных:** checksum всего reviewed corpus, настоящая reviewer provenance, два разных режима разбиения (case-disjoint adaptation и rule-disjoint generalization), underlying aliases + embargo, строгое разделение test prompts и gold.
2. **Согласовать и подключить SFT к тренеру:** adapter сообщений к train-пайплайну, source-only/market review distinction, labels/attention masks, CPU grad smoke и fail-closed GPU readiness **внутри** trainer entrypoint.
3. **Расширить causal input:** H1/H4/D1, 220+ свечей для расчётов, сводки swing/fractal/volume/Alligator/AO/AC с timestamps confirmed_at, книжные короткие цитаты + provenance; проверить, что ответ основан на предъявленных фактах.
4. **Подготовить независимо размеченные положительные/отрицательные/неопределённые кейсы:** в частности, Squat/волны/контргипотезы и кампании с настоящей последовательностью событий. Отдельно оценить авторские правила и торговые результаты.
5. **Исправить измеритель:** строгий полный формат ответов, macro-F1 по решениям, отдельные precision/recall по wave/squat, оценка доводов, safety gates, calibration, независимые two-reviewer ratings и true blind process.
6. **Разделить память по fingerprint/эксперименту и реализовать реальное обучение:** errors из validation → skill taxonomy → approved train examples → LoRA updates → independent validation. Нельзя читать test gold до freeze checkpoint.
7. **Только затем** небольшая controlled QLoRA матрица (например 3 LR × 2 seeds, по бюджету GPU), freezing baseline, rollback на регрессии и однократный финальный unseen walk-forward. Без автоматического выпуска в торговлю.
