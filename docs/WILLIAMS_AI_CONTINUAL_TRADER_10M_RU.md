# Williams AI — непрерывно обучающийся AI-трейдер, а не статичный набор сигналов

**Статус: исследовательский AI, не допущен к автоматической Binance торговле.**
Рабочий репозиторий — только `19wolfalone92/Williams-AI`; не
модифицировать `19wolfalone92/Williams`, основной `main`, ключи и сделки.

## Логика обучения

Обучение теперь состоит из нескольких НЕЗАВИСИМЫХ уровней.

1. **Учебник (знания Вильямса):** существующие личные локальные индексы
   TC1/NTD/TC2/Course, карточки проверенных правил, исправление
   ошибок GGUF, `bootcamp.py`, независимый `algorithm_guard`.
   Рисунки и неразмеченные сложные вложенные волны пока требуют
   дополнительных визуальных эталонов и экспертизы.
2. **Наблюдение рынка:** Binance USD-M Futures OHLCV, AO, AC, Alligator,
   фракталы, «5 волшебных пуль» TC1, многоуровневая структура,
   пятнадцать родных ТФ, приватная история без будущих свечей.
3. **Пережитый результат (новое):** `williams_signal_experience.py`
   генерирует условные, только после полного закрытия временных свечей
   разрешённые **предположительные** WM1/WM2/WM3 сигналы TC2.
   Если триггер на следующей свече не достигнут, сделку не
   выдумывать. При достигнутом триггере консервативно учитываются
   неблагоприятный гэп, структурный стоп, комиссия и проскальзывание,
   а будущий результат записывается как **метка только после
   фактического окончания гипотетического горизонта/SL**.
   Фиксированный исследовательский горизонт — оценка, а не
   разрешённый книжный выход.
4. **Память опыта (новое):** `continual_trader.py` сохраняет опыт в
   приватном SQLite и не переписывает старые результаты; хранит
   отдельный source SHA256 до свечи, на которой результат уже стал
   известен. Добавление будущих котировок не меняет прошлую память.
   История попыток и уже полученных ошибок сохраняется между
   запусками; новый опыт не становится знанием в старом прошлом.
5. **Адаптивный навык (новое):** небольшой числовой классификатор
   реально обновляет коэффициенты только на завершённых бумажных
   WM1/WM2/WM3 сценариях. Все монеты разделяются по **общим
   абсолютным датам** на train / validation / temporal holdout,
   с embargo на незавершённые исходы. Выбирать алгоритм по
   финальному test запрещено. Если обучение не превосходит
   простой прогноз частоты успехов с обучающей части, а
   выбранные решения не имеют положительной доходности после
   транзакционных издержек на validation, навык **ОТКЛОНЯЕТСЯ**;
   вместо сигнала — ABSTAIN.
6. **Применение опыта в мышлении GGUF (новое):** модель
   `reasoning_trial.py --experience-journal ...` получает только
   агрегированную историческую результативность НА МОМЕНТ
   исследуемой закрытой H1, раздельно WM1/2/3 LONG/SHORT.
   Небольшие выборки автоматически «недостаточно данных»,
   будущая результативность не попадает в объяснение.
   Модель не вправе превращать прошлую статистику в гарантированную
   вероятность сделки или обходить книжный `algorithm_guard`.
7. **Исполнение — пока отдельно:** автономные заявки запрещены;
   доступность DEMO, SL ACK, exactly-once, REST recovery после
   частичного заполнения остаются невыполненными шлюзами.
   Ни RAG, ни обучение, ни миллион симуляций не защищают реальные
   деньги без гарантированного биржевого SL.

Это **реальная изменяемая модель навыка и долговременная память**,
но **не** fine-tune весов Qwen3-1.7B GGUF. Для обучения самих
нейросетевых весов нужны отдельный адаптер LoRA/QLoRA, вычислительный
узел, контроль обновлений на слепых периодах и процедура
неоткатной валидации; Android GGUF-сборка этого не умеет.

## Динамический охват ВСЕХ доступных рынков

`binance_universe.py` читает настоящий `/fapi/v1/exchangeInfo`,
отбирает все контракты **TRADING + PERPETUAL + quoteAsset=USDT**.
Нет искусственного списка из 15 фиксированных токенов в Python.
Отдельная проверка публичной Binance API 24.10.2026 наблюдала
**522 текущих подходящих контракта**, тогда как всего в ответе
было **931 строка символов** в разных состояниях.
Количество меняется при новых листингах и делистингах.

Но **522 текущих** — не все исторически когда-либо
существовавшие инструменты. Если изучать только нынешние активные,
возникает survivorship bias. История делистингов требует
отдельного доказанного архива, а не выдуманных свечей.

Пример (команды выполняются только на своём компьютере с
доступом к Binance; никаких секретов ни в GitHub, ни в ChatGPT):

```bash
python -m williams_ai.trader_marathon --discover-universe \
  --venue PUBLIC_USDM \
  --private-universe-snapshot /private/binance-universe-20261024.json
```

Прежде чем обучаться, каждый выбранный контракт и TF должен быть
скачан публичным GET в `DurableWaveHistory` с проверкой
UTC-календаря, окончания свечи, непрерывности и хеша.
Полную историю с листинга нельзя объявлять скачанной
без фактического источника.

После загрузки/проверки реального личного SQLite:

```bash
python -m williams_ai.trader_marathon \
  --history-db /private/binance_usdm_waves.sqlite3 \
  --from-universe-snapshot /private/binance-universe-20261024.json \
  --universe-batch-offset 0 --universe-batch-size 25 \
  --venue PUBLIC_USDM \
  --intervals 15m 1h 4h 1d \
  --private-journal /private/ai-market-experience.sqlite3 \
  --goal 10000000
```

Повторять для следующих батчей `--universe-batch-offset 25,50,75...`.
Опыт остаётся в одной приватной SQLite, но неполный рынок
должен остаться «нет данных»; отсутствие D1 истории не
подменять H1 или архивом другой торговой площадки.

**Недостаёт до исполнения цели 10 млн независимых испытаний:**
масштабное реальное скачивание архивов действующих и делистинговых
инструментов, отметки периода появления/исчезновения токенов,
надёжные WM1/WM2/WM3 книжные эталоны, десятимиллионные
**отдельные замороженные окна решений** без будущего,
перекрёстная квалификация по периоду/инструменту и
слепая просроченная оценка. Даже после этого прибыльность
не гарантирована.

## Продолжение 24.10.2026: онлайн-обучение ПОСЛЕ исхода и настоящая проверка навыка

Добавлен `williams_ai/prequential_skill.py` и включён в
`trader_marathon.py`. В отличие от прежнего однократного обучения
всего train-корпуса, опыт теперь поступает в числовую модель
**только после фактического окончания гипотетического исхода**.
Используется единая временная очередь по всем криптоактивам:
одновременные решения BTC/ETH/SOL не могут подсмотреть
результаты друг друга или будущее рынка. Исправления после
начала validation или final holdout **не обновляют веса**.
Общий момент train cutoff одинаков для всех пар.

Зафиксированные параметры текущего алгоритма:
online logistic SGD, learning rate 0,02, L2 0,002,
порог исследования 0,60, базовое сравнение частоты успеха
по прошлой тренировочной части, разделение 60/20/20
по общим абсолютным датам. Эти параметры не подбирались
по test после получения его результатов.

**Реальный вывод CI на прежней фактической 15-парной
USD-M H1 выборке Binance** (GitHub run `40089906063`):

| Метрика | Validation | Frozen test |
| --- | ---: | ---: |
| Условных WM-позиций (НЕ сделок GGUF) | 462 | 530 |
| Активов | 15 | 15 |
| Brier обновляющегося навыка (меньше лучше) | 0,256807490 | 0,249226275 |
| Brier простого прошлого train prior | 0,225952849 | 0,234744682 |
| Предложенных paper-позиций при P ≥ 0,6 | 4 | 0 |
| Средний net return предложенных paper-позиций | −0,000651199 | не определён |

**Итог испытания: ABSTAIN_NO_VALIDATED_PAPER_ADVANTAGE.**
Результат хуже простой константной модели: переобучаемую
онлайн-модель нельзя считать прогрессом, которому можно
доверять входы. Это не ошибка GitHub CI и не повод
ослаблять порог: система правильно ОТКЛОНЯЕТ навык.
Внутри train было 1354 доразрешённых исхода с реальным
обновлением весов. Никакие 10 млн фиктивных вариаций
комиссий не исправляют эту плохую generalization.

Для 10-миллионной цели добавлена
`PrivateExperience.cumulative_coverage()`.
По всем загруженным частями парам и ТФ приватная SQLite
теперь честно считает **неповторяющиеся комбинации**
`(symbol,interval,decision_at)`; повторный прогон тех же
данных не увеличивает счётчик. Отдельно считаются
WM1/WM2/WM3 исходы, количество активов и фактические
временные границы. Для исходного архива это 2284
уникальных рыночных эпизода и 2369 WM-исходов,
а не 10 млн якобы независимых графиков.

**Стратегия дальнейшего обучения:** сначала накопить больше
разновременных подтверждённых рынков и экспертных
волновых эталонов, затем проверить альтернативный
регуляризованный ученик на будущих ещё не просмотренных
периодах. Нельзя незаметно оптимизировать по уже изученному
final test. Нужен отдельный prospective frozen holdout.
Веса Qwen по-прежнему не были дообучены LoRA;
сейчас собственная память и маленькая числовая
модель адаптируются, а GGUF читает прежние уроки,
книжные страницы и только доступные на тот момент
агрегированные результаты. Это **различные** формы обучения.

Выполненные тесты включают в себя метаморфное отравление
**будущих** меток трёх монет: всё, что было реально известно
до соответствующего времени, включая веса, остаётся
идентичным, хотя будущая оценка меняется. Тесты
проверяют SQLite, UTC-датировки, ошибки, повторные
выгрузки и сохранение отказа от торговли.


## 24.10.2026 — устранена утечка в историческом отборе модели

Раньше онлайн-модель при проверке validation могла учитывать для **оценки и допуска**
исход условной сделки, которая возникла до границы validation, но
**разрешилась ПОСЛЕ** этой границы — уже в периоде финального теста.
Веса SGD от этого не менялись, однако решение «признать модель полезной»
могло косвенно использовать будущие метки. Исправлено:
- train-метрики строятся только из исходов, разрешившихся строго до
  `train_until`; обучение уже было ограничено этими исходами;
- validation-метрики и допуск используют только исходы, завершившиеся
  **строго до** `validation_until`;
- финальный тест по-прежнему оценивает исходы не позднее `observe_until`,
  но не меняет коэффициенты или решение о допуске;
- поле `cutoff_purged_late_resolved_outcomes` показывает исключённые
  примеры по периодам. Метаморфный тест изменяет будущие исходы,
  которые нельзя было знать на границе validation; допуск и метрики
  остаются неизменными.

Кроме того, десятки одновременных сигналов разных монет в один день
больше не могут сами по себе обеспечить порог 10 отобранных сделок.
Для исследовательского допуска требуются условные paper-ситуации
минимум на пяти **разных UTC-днях** и минимум на трёх активах
среди отобранных, а не только среди всех проверенных. Даже пять
разных дней НЕ доказывают статистическую независимость, точность
волновой разметки или прибыльную торгуемую стратегию.

### Замороженные временные границы в исследовательском марафоне

По умолчанию `trader_marathon` подбирает разбиение 60/20/20
из дат **уже имеющейся** выборки. Это только ретроспективный
эксперимент — не честное перспективное слепое испытание.

Для заранее определённого исследования добавлена возможность явно
задать ВСЕ три абсолютные границы через CLI:

```bash
python -m williams_ai.trader_marathon --history-db /private/binance-history.db \
  --venue PUBLIC_USDM --symbols BTCUSDT ETHUSDT SOLUSDT \
  --intervals 1h 4h 1d \
  --private-journal /private/williams-experience.db \
  --train-until 2026-11-01T00:00:00+00:00 \
  --validation-until 2026-12-01T00:00:00+00:00 \
  --observe-until 2027-01-01T00:00:00+00:00
```

**Даты выше только пример формата, не обещание наличия рыночных данных
или будущего исполнения.** Настоящий слепой протокол требует зафиксировать
эти даты и модель ДО начала новых наблюдений, сохранить криптографические
хеши протокола и затем пополнять реальную историю. Сам факт передачи
параметров в CLI не доказывает их предварительную регистрацию.

Ответ содержит `temporal_split_provenance`: либо
`RETROSPECTIVE_DATASET_DERIVED_NOT_PROSPECTIVE_BLIND`,
либо `OPERATOR_SPECIFIED_NOT_INDEPENDENTLY_PROVEN_PREREGISTERED`.
Повторные батчи НЕ создают новых независимых финальных тестов.
Автоторговля и Binance-ордера остаются запрещены.


## 24.10.2026 — учимся прибыльному РЕЗУЛЬТАТУ, а не только угадывать направление

Добавлен исследовательский `williams_ai/causal_trade_quality.py`.
**Даже 80–90% прибыльных сделок могут давать убыток, если редкие
отрицательные исходы значительно больше обычных выигрышей.** Поэтому
одной классификационной вероятности и доли успешных сделок недостаточно.

Новый модуль по каждому из шести источников условных сигналов
`WM1/WM2/WM3 × LONG/SHORT` отдельно:
- берёт только завершённые до границы train исходы paper-сделок;
- считает среднюю чистую доходность после модельных комиссий, соотношение
  суммарных выигрышей и потерь (profit factor) и число разных UTC-дней;
- агрегирует одновременно происходившие события по дате, вместо
  ошибочного обращения с 15 монетами в один день как с 15 независимыми
  рыночными эпохами;
- считает исследовательскую нижнюю границу среднего paper-результата
  (описательная нормальная аппроксимация **без гарантии доверительного
  интервала**, учитывая автокорреляцию);
- не допускает переноса статистики с WM3 на совершенно иной WM1;
- в валидации и тесте использует только замороженный опыт из train,
  не читает outcome самого кандидата до решения, отсекает незавершённые
  исходы каждого периода; для одной пары не учитывает одновременно
  несколько overlapping paper-позиций.

**Это учебная диагностика, а не самостоятельная прибыльная
торговая стратегия.** Она не воспроизводит полные книжные кампании,
не включает реальную частичную ликвидность/проскальзывание, funding,
реальные позиции, плечо, единую portfolio equity или подтверждённый
биржей стоп. `profit_quality_frozen_research_only` не может разрешать
торговлю независимо от полученных положительных оценок. Результаты
старого теста остаются использованными и не становятся новым blind
holdout только из-за дополнительной метрики.

Также приватная память `past_feedback()` теперь сообщает модели
не только число прошлых выигрышных сценариев, но и:
- прошлый net paper profit factor (или `null`, если знаменатель нулевой);
- историческую безубыточную долю выигрышей, рассчитанную из
  средних выигрыша/убытка;
- число разных UTC-дней наблюдения с пометкой о зависимости данных.

GGUF получает эти значения **как неавторитетные прошлые опыты**,
а не как сигнал или гарантию положительного дохода.

### Что конкретно прочитано в четырёх первоисточниках для этой правки

### Новое: настоящее численное обучение на чистую доходность вместо одного win rate

Добавлен `williams_ai/prequential_net_skill.py` — отдельный
**причинный обучаемый online-регрессор**. Он обновляет числовые веса
только после завершения исторических условных WM1/WM2/WM3 событий
в общем хронологическом времени для всех пар.

В отличие от Brier-классификатора по положительному/отрицательному
исходу, новый учебный навык непосредственно прогнозирует
**чистую ожидаемую доходность условного эпизода после
модельных комиссий и проскальзывания**. Используется
регуляризованная линейная модель с Huber-ограничением
ошибки на градиенте, общими признаками AO/AC/Аллигатора и
раздельными сдвигами WM1/WM2/WM3 LONG/SHORT.
Тестовая ошибка измеряется по **необрезанным** реальным
paper-исходам, включая большие потери.

Фиксированные параметры исследования: learning rate 0.004,
L2 0.0005, Huber delta 0.04, порог условно положительного
прогноза 0.003. Ничего не подбиралось по финальным test
исходам при написании этой версии. Кандидат сравнивается
с более честной базой — отдельной **средней исторической
доходностью каждого setup+side**, известной на границе train.

Квалификация может только пометить модель
`PROMISING_PAPER_ONLY_NEEDS_NEW_PROSPECTIVE_DATA` и только
при выполнении заданных требований к validation: сниженная
ошибка net-return, минимум 12 выбранных эпизодов,
минимум 6 UTC-дней, три актива, положительная средняя чистая
доходность и paper-profit-factor > 1.2.
Иначе **ABSTAIN**. Финальный тест только показывает результат,
не переобучает и не изменяет принятый ранее критерий.
**Любой положительный результат остаётся исключительно
исследовательским**, без прав на Binance-ордера.

Это не настоящая интерпретация всех волновых рисунков
Qwen и не обучение весов GGUF, хотя это реальное
обновление числового навыка на завершённом прошлом опыте.
Реальную прибыльность подтвердит только отдельная
будущая выборка, а затем независимая приёмка DEMO
исполнения с защитными стопами.
