# Williams AI — непрерывно обучающийся AI-трейдер, а не статичный набор сигналов

**Статус: исследовательский AI, не допущен к автоматической Binance торговле.**
Рабочий репозиторий — только `19wolfalone92/Williams-AI`; не
модифицировать `19wolfalone92/Williams`, основной `main`, ключи и сделки.

## Логика обучения

Обучение теперь состоит из нескольких НЕЗАВИСИМЫХ уровней.

1. **Учебник (знания Вильямса):** существующие личные локальные индексы
   TC1/NTD/TC2/Course, карточки проверенных правил, исправление
   ошибок GGUF, `bootcamp.py`, независимый `algorithm_guard`.
   Рисунки и неразмеченные сложные вложенные волны пока требуют
   дополнительных визуальных эталонов и экспертизы.
2. **Наблюдение рынка:** Binance USD-M Futures OHLCV, AO, AC, Alligator,
   фракталы, «5 волшебных пуль» TC1, многоуровневая структура,
   пятнадцать родных ТФ, приватная история без будущих свечей.
3. **Пережитый результат (новое):** `williams_signal_experience.py`
   генерирует условные, только после полного закрытия временных свечей
   разрешённые **предположительные** WM1/WM2/WM3 сигналы TC2.
   Если триггер на следующей свече не достигнут, сделку не
   выдумывать. При достигнутом триггере консервативно учитываются
   неблагоприятный гэп, структурный стоп, комиссия и проскальзывание,
   а будущий результат записывается как **метка только после
   фактического окончания гипотетического горизонта/SL**.
   Фиксированный исследовательский горизонт — оценка, а не
   разрешённый книжный выход.
4. **Память опыта (новое):** `continual_trader.py` сохраняет опыт в
   приватном SQLite и не переписывает старые результаты; хранит
   отдельный source SHA256 до свечи, на которой результат уже стал
   известен. Добавление будущих котировок не меняет прошлую память.
   История попыток и уже полученных ошибок сохраняется между
   запусками; новый опыт не становится знанием в старом прошлом.
5. **Адаптивный навык (новое):** небольшой числовой классификатор
   реально обновляет коэффициенты только на завершённых бумажных
   WM1/WM2/WM3 сценариях. Все монеты разделяются по **общим
   абсолютным датам** на train / validation / temporal holdout,
   с embargo на незавершённые исходы. Выбирать алгоритм по
   финальному test запрещено. Если обучение не превосходит
   простой прогноз частоты успехов с обучающей части, а
   выбранные решения не имеют положительной доходности после
   транзакционных издержек на validation, навык **ОТКЛОНЯЕТСЯ**;
   вместо сигнала — ABSTAIN.
6. **Применение опыта в мышлении GGUF (новое):** модель
   `reasoning_trial.py --experience-journal ...` получает только
   агрегированную историческую результативность НА МОМЕНТ
   исследуемой закрытой H1, раздельно WM1/2/3 LONG/SHORT.
   Небольшие выборки автоматически «недостаточно данных»,
   будущая результативность не попадает в объяснение.
   Модель не вправе превращать прошлую статистику в гарантированную
   вероятность сделки или обходить книжный `algorithm_guard`.
7. **Исполнение — пока отдельно:** автономные заявки запрещены;
   доступность DEMO, SL ACK, exactly-once, REST recovery после
   частичного заполнения остаются невыполненными шлюзами.
   Ни RAG, ни обучение, ни миллион симуляций не защищают реальные
   деньги без гарантированного биржевого SL.

Это **реальная изменяемая модель навыка и долговременная память**,
но **не** fine-tune весов Qwen3-1.7B GGUF. Для обучения самих
нейросетевых весов нужны отдельный адаптер LoRA/QLoRA, вычислительный
узел, контроль обновлений на слепых периодах и процедура
неоткатной валидации; Android GGUF-сборка этого не умеет.

## Динамический охват ВСЕХ доступных рынков

`binance_universe.py` читает настоящий `/fapi/v1/exchangeInfo`,
отбирает все контракты **TRADING + PERPETUAL + quoteAsset=USDT**.
Нет искусственного списка из 15 фиксированных токенов в Python.
Отдельная проверка публичной Binance API 24.10.2026 наблюдала
**522 текущих подходящих контракта**, тогда как всего в ответе
было **931 строка символов** в разных состояниях.
Количество меняется при новых листингах и делистингах.

Но **522 текущих** — не все исторически когда-либо
существовавшие инструменты. Если изучать только нынешние активные,
возникает survivorship bias. История делистингов требует
отдельного доказанного архива, а не выдуманных свечей.

Пример (команды выполняются только на своём компьютере с
доступом к Binance; никаких секретов ни в GitHub, ни в ChatGPT):

```bash
python -m williams_ai.trader_marathon --discover-universe \
  --venue PUBLIC_USDM \
  --private-universe-snapshot /private/binance-universe-20261024.json
```

Прежде чем обучаться, каждый выбранный контракт и TF должен быть
скачан публичным GET в `DurableWaveHistory` с проверкой
UTC-календаря, окончания свечи, непрерывности и хеша.
Полную историю с листинга нельзя объявлять скачанной
без фактического источника.

После загрузки/проверки реального личного SQLite:

```bash
python -m williams_ai.trader_marathon \
  --history-db /private/binance_usdm_waves.sqlite3 \
  --from-universe-snapshot /private/binance-universe-20261024.json \
  --universe-batch-offset 0 --universe-batch-size 25 \
  --venue PUBLIC_USDM \
  --intervals 15m 1h 4h 1d \
  --private-journal /private/ai-market-experience.sqlite3 \
  --goal 10000000
```

Повторять для следующих батчей `--universe-batch-offset 25,50,75...`.
Опыт остаётся в одной приватной SQLite, но неполный рынок
должен остаться «нет данных»; отсутствие D1 истории не
подменять H1 или архивом другой торговой площадки.

**Недостаёт до исполнения цели 10 млн независимых испытаний:**
масштабное реальное скачивание архивов действующих и делистинговых
инструментов, отметки периода появления/исчезновения токенов,
надёжные WM1/WM2/WM3 книжные эталоны, десятимиллионные
**отдельные замороженные окна решений** без будущего,
перекрёстная квалификация по периоду/инструменту и
слепая просроченная оценка. Даже после этого прибыльность
не гарантирована.

## Полный обучающий цикл без подмены реальным трейдингом

```bash
# Получить исходные 15 пар прежней исторической выборки
python -m williams_ai.trader_marathon --frozen-fixture \
  --private-journal /private/my_ai_experience.sqlite3

# Доказательный 10-миллионный анализ ИЗДЕРЖЕК, не 10м независимых сделок
python -m williams_ai.ten_million_stress \
  --private-journal /private/my_ai_experience.sqlite3 \
  --known-at 2026-10-24T00:00:00+00:00 --target 10000000

# Извлечь прежние выученные ошибки на момент прошлого графика TC2
python -m williams_ai.reasoning_trial --symbol ETHUSDT \
  --bar-index 1000 --edition TC2 \
  --local-model /private/Qwen3-1.7B-Q4_K_M.gguf \
  --experience-journal /private/my_ai_experience.sqlite3
```

В примере конкретный файл GGUF — пользовательский локальный,
его загрузка/хэш должны быть проверены отдельно. Ни одна из
команд не отправляет Binance-ордера.

## P0 перед реальным AI Demo

Дальше нужны **не ещё миллионы похожих грид-прогонов**,
а (1) истинная книжная экспертная разметка волн,
(2) стабильный плюс на будущих временных/монетных
выборках после комиссий с учётом correlated drawdown,
(3) подтверждённый Binance DEMO SL → fill → сопровождение
→ reconnect, (4) автономный исполнительный контур,
физически разделённый с самоизменяемым AI.
До того момента реальный GGUF может совершенствовать
объяснения и сохранять знания и ошибки, но без
самовольных ставок или денежных потерь.
