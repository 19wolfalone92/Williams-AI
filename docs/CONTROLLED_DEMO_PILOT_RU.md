# Williams AI — первая контролируемая сделка Binance Futures DEMO

**Среда:** только Binance Futures DEMO (https://demo-fapi.binance.com), только ETHUSDT,
только ручная сделка с операторским подтверждением, без реальных денег и без приказов от
Qwen/LLM. Торговый Williams, Android APK и `main` НЕ затронуты.

## Почему доступно не всё

Текущая Qwen может прочитать график и предложить WM1/WM2/WM3, но независимые
исторические проверки всё ещё показывают ошибки прогноза и отсутствие подтверждённого
торгового преимущества. Передавать её произвольный JSON в Binance запрещено.

Уже созданный `williams_ai.demo_futures` умеет размещать защитный
`STOP_MARKET` через DEMO Algo API **до** входа и проверять его наличие.
Однако пока **нет реального Binance DEMO подтверждения**, что биржа примет такой
`closePosition=true` SL без заранее открытой позиции. Если биржа его отклонит,
алгоритм откажется от входа. Менять порядок на «вход без подтверждённого SL»
нельзя. Моковый CI тест не заменяет биржевой ACK.

Существующий Android `com.williamsai.offline` НЕ связан с DEMO исполнением;
ни эта ветка, ни документ не превращают APK в автономного торгового агента.

## P0: порядок проверки без торговых ключей

На компьютере с Python 3.11 из корня исходников текущей **исследовательской
ветки**, используя **только будущую DEMO площадку**, выполнить после
проверки рыночного состояния:

```bash
python -m unittest discover -s tests -p 'test_williams_ai_demo*.py' -v
python -m williams_ai.demo_pilot_cli check \
  --symbol ETHUSDT --side BUY --quantity <safe_eth_amount> \
  --stop <structurally_valid_tick_aligned_demo_stop>
```

Остановиться, если публичный DEMO `/time`, `/exchangeInfo`,
`/premiumIndex` недоступен, время отличается от локального >10 сек,
маркер цены устарел, контракт не `TRADING`, нет фильтров, неверна
точность стопа/объёма или риск превышает **1 DEMO USDT** / **50 DEMO USDT**
номинала. Эта проверка не требует ключей и НИКОГДА не создаёт заявок.

**Не используйте указанные числа как конкретные уровень/цену входа.**
Пользователь обязан сам выбрать инструментальное количество и SL по
актуальному рынку, а не копировать старую цену или вывод LLM.

## P0: один-единственный supervised DEMO вход (ключи только у пользователя)

**Не передавайте API key и secret ChatGPT, GitHub Actions или публичным файлам**.
На Binance DEMO создать отдельную учётную запись и отдельные API-ключи,
не связанные с production-аккаунтом и основным Williams.

В интерактивном терминале пользователя:

```bash
python -m williams_ai.demo_pilot_cli supervised-send \
 --symbol ETHUSDT --side BUY \
 --quantity <safe_eth_amount> \
 --stop <structurally_valid_tick_aligned_demo_stop> \
 --journal /private/williams_ai_demo_pilot.sqlite3
```

Путь к `--journal` должен находиться в существующем приватном каталоге;
файл создаётся с правами 0600. Программа требует две явно введённые фразы:
`DEMO_ACCOUNT_ONLY` и `PLACE_DEMO_ORDER`. До второй фразы биржевая
заявка не отправляется.

После второй фразы журнал **синхронно резервирует одно намерение через
SQLite BEGIN IMMEDIATE**, до первой биржевой мутации. Если сеть упадёт,
процесс завершится или приложение будет запущено снова, такой же вход
заблокирован. Состояние никогда не сбрасывается автоматически.

```bash
python -m williams_ai.demo_pilot_cli status \
 --journal /private/williams_ai_demo_pilot.sqlite3
```

Важно: статус `UNKNOWN_UNTIL_EXCHANGE_RECONCILED` — не ошибка UI.
Это осознанный запрет на автоматический повтор до ручной сверки позиции,
сделок, стопов и клиентских идентификаторов на Binance DEMO.
**Нельзя просто удалить журнал, пока есть неопределённые ордера/позиции.**
Отдельной автоматической процедуры безопасного сброса сейчас нет.

## Критерии перехода от первого пилота к автономному Testnet

1. На реальной DEMO площадке доказан порядок фактических ACK:
   стоп до входа → одна исполненная заявка → stop ещё действителен.
   Если предустановка при нулевой позиции невозможна, **NO_TRADE** до
   новой независимо проверенной схемы защиты.
2. Каждая попытка не может повториться после таймаута, 5xx, падения
   Android, перезапуска Python или смены сети. Есть сохранённый
   clientOrderId/clientAlgoId и REST reconciliation. Текущий одинарный
   журнал решает только **первый** блок на отправку, не даёт полноценной
   реставрации состояния и не является завершённой исполнительной FSM.
3. Вход и выход привязаны к **фактическому** Binance `FILLED`, количеству,
   средней цене, счёту и актуальному защитному стопу, а не сообщению LLM.
4. Положительный протокол fault injection: отсутствует стоп, отмена
   стопа, частичное исполнение, разрыв WebSocket, 5xx, рестарт,
   ручная операция на счёте, неверный символ/время, обновление APK.
5. Перед автономным запуском — независимый источник доказанного сигнала
   WM1/WM2/WM3, книга-профиль кампании, пересчёт риска и единый владелец
   позиции на пару. Изоляция реальных ключей и DEMO обязательна.
6. **Автономная торговля и LIVE остаются DISABLED** до подтверждения
   всех P0 гейтов и отдельного решения владельца.

Критически важно: программные тесты и сборка APK **не** являются настоящей
приёмкой DEMO. В данном PR не выполнена подписанная биржевая заявка и не
разрешена самостоятельная торговля AI.


## Стадия 0: AI в теневом режиме прямо на Binance Futures DEMO

Добавлен отдельный строго read-only модуль `williams_ai.demo_shadow`:
он читает **только DEMO** публичные H1 свечи `/fapi/v1/klines`, отбрасывает
незакрытую свечу, проверяет последовательность и свежесть, восстанавливает
доступные полностью закрытые H4/D1, строит H1 контекст Вильямса и кандидатов
WM1/WM2/WM3. Он **не** знает приватного счёта и **не** отправляет заявки.

```bash
python -m williams_ai.demo_shadow
```

Для реальной локальной Qwen3 (не mock), после проверки истинного SHA-256
файла весов:

```bash
python -m williams_ai.demo_shadow \
  --model /private/Qwen3-1.7B-Q4_K_M.gguf \
  --expected-sha256 <SHA256_REAL_GGUF>
```

Ответы LLM проходят независимый контроль по TC2. Если GGUF утверждает
выдуманную биржевую заявку, это недопустимо. Наличие признака WM3
**не** превращается в исполняемый приказ, а `NO_SETUP` не считается
безошибочным знанием книг. Этот процесс исполняется разово в Python,
не на Android и не постоянно в фоне.

### Внешняя сетевая проверка 24 октября 2026

Read-only GitHub Actions попытка проверить `demo-fapi.binance.com`
**неуспешна — HTTP 451**. Это блокировка доступа из региона GitHub runner;
она НЕ является доказательством ошибки биржевых алгоритмов и НЕ может
расцениваться как успешное соединение. P0 `PUBLIC_DEMO_CONNECTIVITY`
сохраняет состояние **BLOCKED**, даже если все mock/unit тесты зелёные.
Проверку источника следует провести с устройства/компьютера пользователя
при разрешённом доступе к Demo. **Никаких ключей в GitHub**.

### Исправления в существующем исполнительном контуре

- Старый `williams_ai.demo_cli --send` запрещён: нет долговременного
  журнала и не соблюдается пилотный лимит одной кампании.
- Новый `demo_pilot_cli supervised-send` сохраняет намерение на диске до
  первого биржевого POST, ограничивает 50 DEMO USDT номинала и 1 DEMO USDT
  расчётного риска; требует два подтверждения и оператора.
- После ответа MARKET `FILLED` требуются числовой фактический
  `executedQty`, `orderId`, независимый подписанный REST GET по заказу,
  сверка `/fapi/v3/positionRisk` и подтверждение защитного Algo SL.
  Несоответствие → блокировка и запрет повторной подачи; при известном
  FILLED предусмотрена аварийная попытка reduce-only, но фактическое
  закрытие всё равно требует отдельной проверки.
- Недоступность DEMO REST, отсутствие SL до входа, неопределённый
  результат после таймаута или несовпадение количества **не должны**
  считаться успешной пилотной сделкой.

**Отсутствующая приёмка:** живое подписанное DEMO испытание
STOP_MARKET до позиции + подтверждение исполнения + рестарт/REST-восстановление.
Ни CI, ни модель не может подменять эти фактические биржевые события.
