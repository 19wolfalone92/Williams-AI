# Williams AI — реальное корректирующее QLoRA-обучение, 10.11.2026

**Статус:** одна отдельная научно-исследовательская GPU-сессия на ветке `research/deep-corrective-20261110` после CI и проверки квоты. Никакого разрешения на торговлю, никакого изменения Williams Bot и main. Это не публикация нового релиза модели.

## Повторное использование проверенных весов

- Вход: Qwen/Qwen3-4B, зафиксированная ревизия `3fb356690bbdae7353c94efb3eecdce276e6ed1c`, NF4 4-bit double quant, LoRA rank16 alpha32, 33,030,144 обучаемых параметра, FP16 GradScaler; подлинные 2×Tesla T4 проверяются GPU worker.
- Продолжаем **с проверенного адаптера 6 ноября**, SHA-256 `d961d7e7406d255e699da3959a3c67606330fee191807627b15de35ac4508ca7`, получаемого из собственного Kaggle kernel `williams-ai-joint-rules-20261106`. *Это не последняя модель 7 ноября*: ее архив зашифрован отдельно и его нельзя выдавать за доступный.
- Новый неизменяемый приватный kernel slug: `williams-ai-deep-corrective-20261110-r1`. При существующем kernel повторная отправка запрещена. Прежде записи сверяем доступную **бесплатную** квоту, наличие родительского адаптера, исходные 4 книги в исходном зашифрованном транспортном контейнере, неизменность схемы, исключение test текстов и отдельный контроль `stop`.
- Источник данных: прежние закрытые исторические рыночные окна с непересекающимися train/validation/test по времени, четыре приватные книги (не попадают в публичные артефакты), плюс **новые детерминированные учебные упражнения** на риск и AC и учебные случаи отсутствия подтверждённого STOP.
- Для проверок входов/выходов используется наблюдательная TC2 proxy-логика, **не экспертная разметка настоящих волн**. Старый 280-case экзамен 7 ноября уже раскрыт: трактуется как **регрессионная проверка**, а не новый blind holdout. Новые 16 числовых test-параметров с отдельным seed отобраны до запуска и не отправляются GPU в виде ответов. Это по-прежнему не доказательство преимущества на бирже.

## Параметры одного ограниченного запуска

| Параметр | Значение |

| GPU | Kaggle free Tesla T4 ×2, DDP/NCCL |

Изменения в материале: к текущему train добавляются новые seed-separated risk/AC задачи и случаи `stop_ack=false` с независимой перегенерацией эталона. Для определения точек сохранено усиленное покрытие всех 4 книг (повторы исходных train-окон увеличены с 1 до 2). Значения параметров ограничены и зафиксированы в Git. Конвейер выбирает точку только по development, не по финальному экзамену. Остановить можно изменением `experiments/deep-corrective-control.json` на `{"run_slug":"williams-ai-deep-corrective-20261110-r1","stop":true}`; watcher в worker останавливает тренировку fail-closed при недоступности контроля >300 секунд.

## Границы контроля и архивации

- Результат от Kaggle в публичном GitHub Actions **только в зашифрованном виде** с X25519+HKDF+AESGCM. Публичный ключ выводится из уже установленного токена Kaggle через приватную функцию на runner, **без записи или печати самого токена либо приватного ключа**; для будущего извлечения необходим тот же секретный токен. Ротация секрета до резервного копирования ключа сделает архив недоступным.
- Перед завершением независимая CPU-проверка сверяет записанные веса, число обновлений, всю матрицу ответов, freeze перед экзаменом, разнесение источников, пороги и SHA-256. Вне GitHub есть личный архив исследований. Приватные PDF и лицензионный текст не публикуются.
- Если workflow `failure` или `cancelled`, нельзя утверждать, что новое обучение завершено. Даже успешный GPU run при `research_gate_passed=false` — лишь исследовательский адаптер. Никаких ордеров, интеграции с APK, ослабления STOP или перехода модели в `main` без нового независимого допуска.
- Инициирование GPU разрешено только при подтверждённой бесплатной квоте и **после успешного CPU CI**. Документ не означает, что работа уже запущена. Итог фиксируется по реальной ссылке Actions и receipt.

1. CPU: `python -m unittest tests.test_williams_ai_deep_corrective_20261110 -v`; `python -m unittest tests.test_williams_ai_market_decision -v`.
2. После успешного CPU CI событие добавления `experiments/deep-corrective-start.json` запускает workflow `.github/workflows/ai-deep-corrective-gpu-20261110.yml` один раз. Скрипт `scripts/ai_run_deep_corrective_kaggle.py` использует приватные ресурсы только на пользовательской CI/Kaggle инфраструктуре.
3. Контролировать в GitHub Actions статус `Williams AI ACTUAL Qwen3-4B deep corrective dual-T4 QLoRA`; при `success` смотреть квитанцию и `research_gate_passed` отдельно. Выполненный GitHub-run не гарантирует прогресса качества и не даёт торговый допуск.
