# Williams AI — автономное управление 10 потоками через 5 Tasks

Дата ревизии: 2026-11-07. Это эксплуатационный документ, НЕ доказательство изменения модели в ходе этой ревизии.

## Ограничения и реальная инфраструктура

- На текущем тарифе ChatGPT попытка создать пятую дополнительную активную задачу вернула `too_many_active_automations`: доступно **5 активных scheduled tasks всего**. Четыре пары исследователей + одна центральная задача покрывают все десять GitHub Issues. Это НЕ десять одновременно работающих сессий чата.
- Расписание относится к `Europe/Amsterdam`, режим flexible daily: около 09:00 TC1+NTD, 10:00 TC2+Course, 11:00 Waves+Indicators, 12:00 TC2 lifecycle+H1/H4/D1, около 19:00 независимая оценка + единый тренер. Запуск может сдвигаться. Проверяйте фактические runtime/permissions.
- Исследовательские Tasks выполняют только GitHub read / результаты в **своих issue comments**, НЕ пишут код; текущий `AGENTS.md` разрешает одновременно только **одного автора кода**.
- Центральный task читает результаты, проверяет PR и CI, и лишь при соблюдении single-writer preflight может делать **одну** безопасную обратимую запись в изолированной ветке/draft PR. Без блокировки и разрешённого владения кодом — только issue-level отчёт.
- Issues: #58–#65 = 8 исследовательских потоков, #66 = QA, #67 = training orchestration; #69 = общий журнал. Протокол в draft PR #68.

## Антизастойная очередь и честное управление

- В каждом запуске перечитать Issue, последние комментарии, связанные PR/CI, отметить точную дату и результаты.
- Гарантировать отсутствие дублей, особенно с PR #53/#55; не создавать вторую Qwen3-4B тренировочную линию.
- По одной малой проверяемой микроработе: генерация авторского тестового вектора, независимого golden test, библиографической проверки или коррекции ограниченного кода. Не производить бессмысленные проверки и одинаковые отчёты без прогресса.
- Если первоисточник недоступен: пометка DRAFT/UNVERIFIED, не публиковать PDF/OCR и не фабриковать edition/page.
- Две одинаковые ошибки => BLOCKED с точным сообщением, после этого выбрать независимую часть задачи.
- Отчитываться строками `checked cases | verified cases | tests passed/failed | checkpoint hash and admission verdict | blockers | next atomic action`. Важны изменения, а не количество сообщений.
- Ни один research task не имеет права делать merge, торговать, вводить API keys или запускать платные вычисления. Квоты бесплатного GPU проверяются до запуска. Глобальная модель получает новую версию только после независимой QA, versioned artifact, проверки regression и явного допуска.

## Что здесь нельзя автоматизировать полностью

ChatGPT scheduled task не гарантирует создание другого чата, постоянный доступ к GPU/книгам или чтение ответов из всех десяти частных разговоров. **Единственный журнал для координации — GitHub issue/PR/CI/artifact**. Надёжный вычислительный запуск — отдельная согласованная GitHub Actions / Kaggle схема, а не обещание бессрочной фоновой работы.
