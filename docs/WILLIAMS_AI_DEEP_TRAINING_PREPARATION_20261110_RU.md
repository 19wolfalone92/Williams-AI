## Приоритеты следующего этапа

1. **Безопасность: STOP и риск.** Целевая практика — независимый расчёт размера позиции (Decimal, округление вниз, fees/slippage, цена шага, precision, плечо и маржа), недостающий защитный STOP, stop acknowledgment, pending entry, отмена/рестарт, long/short. Числовые эталоны генерировать другой программой и проверять контрольными инвариантами; не подменять правильный риск подсказкой ответов финального экзамена. Модель должна уметь воздержаться при недостатке данных. **Не делегировать фактическое управление SL нейросети**: проверка предельного риска и STOP должна оставаться в отдельной детерминированной fail-closed логике.
2. **AC, AO и Alligator.** Отдельные контрпримеры к AC-правилам при пересечении нулевой линии, одинаковые значения, разрывы, неполные свечи и противоречащий тренд H4/D1. Перепроверить TC1/NTD/TC2/Course на реальных страницах и рисунках; если исходник или визуальное подтверждение отсутствует, ставить `UNVERIFIED`, исключая из train.
3. **Волны/фракталы.** Проверенные отметки человека для волн, альтернативные разметки, timestamp подтверждения экстремумов, правила ангуляции WM1 и TC2, без знания будущих баров. Синтетические skeleton/wave proxy **не** выдавать за экспертное понимание.
4. **Сценарии кампаний.** Планирование входа stop-entry, подтверждение исполнения, добавления, перенос STOP, выход, перезапуск, отмена, неизвестный статус API. Явный `WAIT/ABSTAIN` и отдельные детерминированные проверки.
5. **Антирегрессия четырёх книг.** Перемешать проверенные корректирующие уроки с сохранением ранее освоенного материала; отдельно измерять source/practice loss TC1, NTD, TC2, Course и проверять сохранение каждого раздела. Не повышать число эпох/learning-rate наугад.

## GPU/QLoRA конфигурация и безопасность

- **Стартовать от действующего кода PR #55**, не создавать вторую несовместимую тренировочную линию. База — официальный фиксированный `Qwen/Qwen3-4B`, revision `3fb356690bbdae7353c94efb3eecdce276e6ed1c`; 4-bit NF4, double quant; LoRA rank16/alpha32, только LoRA матрицы trainable; 2× Tesla T4 / DDP; FP16 с GradScaler (T4 не требовать BF16).
- Сохранять proven-работающие micro-batch=1 на GPU; увеличение batch 4–8 допустимо только после CUDA OOM smoke и проверки effective batch. LR исходных подтверждённых циклов — 5e-6 или 7e-6, **не переключать слепо на 2e-4**. Короткий pilot со снимком baseline, обязательной оценкой каждого критического разреза и откатом при регрессии.
- GPU-префлайт перед подачей: доступность именно двух T4, проверенная свободная **текущая** квота, отсутствие активного private kernel той же линии, проверенные HF/base+tokenizer hash, доступная собственная adapter lineage и storage. Никаких платных fallback или скрытого чтения ключей. Если `sealed` 07.11 не открыть законным способом, явно выбрать документированный старый checkpoint 06.11, **не выдавая его за последний**.
- Идемпотентная запись `dataset_sha`, `model_revision`, `tokenizer_sha`, `adapter_sha`, `trainer_commit`, `seed`, `trainable_params`, `rank/alpha`, `batch/accumulation`, `optimizer steps`, `GPU/device`, `checkpoint_sha`. Отдельный архив `optimizer/scheduler/scaler/RNG` нужен для продолжения, один LoRA `.safetensors` недостаточен для точного возобновления траектории.

## Предварительно зафиксированные критерии перехода

- Все critical: **0 превышений риск-бюджета**, **0 пропусков обязательного защитного STOP**, 0 действий с разрешением исполнения в исследовательском режиме, 0 неподтверждённых торговых действий, 0 утечек future data.
- Сохранять существующие пороги PR #55: >=80% суммарной точности по каждому закрытому набору, >=75% по отдельному правилу и +5 процентных пунктов к обеим выбранным baseline там, где этот критерий был предусмотрен; никаких константных ответов. Отдельно нулевые критические ошибки в STOP/risk, улучшение по новым unseen cohort и пройденные текстовые source/practice-gates по каждой книге.
- При fail любого заранее заданного gate оставить прежний champion, сохранить challenger в исследовательском архиве; **не добавлять его в main/Android/GGUF и не отправлять даже DEMO-ордера**. Точность учебных JSON и отсутствие lookahead не равны прибыльности: для торговли потребуется независимая биржевая проверка, комиссии/funding/проскальзывание, стопы и real-time recovery.
