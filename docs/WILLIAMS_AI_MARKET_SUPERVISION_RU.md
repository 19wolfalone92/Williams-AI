# Проверяемые рыночные примеры для Qwen

## Изменение

По умолчанию `private_lora` требует не только проверенную теорию четырёх
источников, но и рыночные примеры: минимум 24 train, 8 validation и 8 test,
с TC1/NTD/TC2/COURSE в каждой части. Текстовый эксперимент возможен только
с явным `--source-only-research`; его нельзя называть обучением торговле.
Общие минимумы набора остаются 64/16/16. Это технические минимумы запуска,
а не доказательство достаточности данных или качества AI.

## Схема и независимость

К обычной строке private_lora добавляются `market_context` и
`independent_reviews`. Контекст содержит 220–1500 непрерывных завершённых
свечей, площадку, символ, ТФ, cutoff, tick_size и контрольную сумму.
Разрешены M5/M15/H1/H4/H6/D1 с точным UTC-выравниванием закрытия Binance.
Форма проверяется до импорта CUDA/Transformers.

Две рецензии содержат `reviewer_id`, `reviewed_at`, `lesson_sha256`.
Разные ID и даты — декларации людей, а не техническое доказательство их
личности, профессионализма или независимости. Контрольная сумма не является
цифровой подписью. Её нельзя автоматически заполнять от имени эксперта.

Перед рецензированием люди независимо рассматривают исходную страницу,
фигуру и закрытый график. После согласования финального ответа каждый
проверяет именно этот ответ. Хеш вычисляется функцией
`chart_supervision.lesson_commitment` для полной строки с финальными
question/answer/source/rule/split/market_context. Любое изменение ответа,
вопроса, правила, раздела или свечи аннулирует обе рецензии. Спорные случаи
остаются PENDING, без выдуманной правильной разметки.

История одного символа не пересекается между train/validation/test,
включая разные ТФ; дополнительно действует 24-часовой зазор. Проверка
только разных хешей или разных дат cutoff недостаточна: соседние скользящие
окна почти одинаковы. Совпадающие окна внутри одной части допустимы, но
не являются независимыми статистическими наблюдениями. Корреляция разных
криптовалют этой проверкой не устраняется.

## Воспроизводимая подготовка

`private_review_queue.source_rules_by_split()` задаёт единое разбиение
правил для текстовых и рыночных примеров. Одно правило не попадает в
разные части. `market_review_queue` создаёт задания без экспертных ответов,
по заранее выбранным символам и последним общим завершённым UTC-дням.

```bash
python -m williams_ai.market_review_queue \
  --contexts /private/contexts.json \
  --partitions /private/symbol_partitions.json \
  --output-private-jsonl /private/market_review_queue.jsonl
python tools/render_ai_market_review.py \
  /private/market_review_queue.jsonl /private/charts
```

Генератор намеренно оставляет `answer` пустым, статус PENDING и массив
рецензий пустым. Такой набор не допускается к обучению. Распределение по
исходам/PnL не применяется. Это историческая выборка, не prospective-тест;
проверка действующих часов биржи не заявляется.

Подготовленный 25.10.2026 набор: 15 символов × 8 UTC-дней
15–22.10.2026 = 120 графиков; 72/24/24 по разделам, 30 на источник.
Дополнительно — 148 текстовых кандидатов по 37 просмотренным карточкам.
Ответы по графикам и независимые рецензии не подготовлены. Эти числа не
означают 268 проверенных уроков и не доказывают изучение всех страниц книг.

## Действительное обучение и пределы проверки

```bash
python -m williams_ai.private_lora \
  --reviewed-jsonl /private/approved.jsonl \
  --local-hf-model /private/qwen-hf \
  --private-adapter-output /private/new-adapter \
  --max-tokens 4096 --audit-only
```

Удаление `--audit-only` запускает реальные LoRA-обновления только при наличии
локальной обучаемой Qwen, CUDA GPU, необходимых библиотек и проверенных данных.
Нельзя запускать обучение на автоматически одобренных ответах AI.
Контекст в токенах не обрезается: слишком длинный пример отклоняется.

В модель поступает численное представление закрытого графика: последние
16 OHLCV, причинно сдвинутый Alligator, AO/AC, строгие подтверждённые фракталы
и диапазоны 34/100/140/220 баров. Это не изображение и не полноценная
визуальная/MTF-волновая интерпретация. Объём Binance не считается tick volume.
Шаблон полного диалога берётся у токенизатора; весь prompt маскируется в
loss, обучается ответ эксперта. Несовместимый prompt prefix отклоняется.

Тестовые ответы проверяются аудитором схемы, но не передаются Trainer и
не используются для выбора адаптера. Снижение validation loss допускает
только сохранение исследовательского адаптера. Нужны отдельные новые
экспертные графики и полный торговый replay после издержек.

Настоящее обучение весов, положительное ожидание новой Qwen, независимый
gold benchmark, подписанный Demo fill/SL/restart/exit и приёмка телефона
пока не подтверждены. Этот путь не разрешает модели отправлять ордера.

## Черновики аналитика для координатора

`williams_ai.review_drafts` формирует отдельные разборы по всем 120 срезам,
не заполняя поле `answer` исходной очереди и не создавая человеческие
рецензии. Это детерминированный причинный teacher, не ответы обученной Qwen.
Формат черновиков намеренно несовместим с входом LoRA. Его нельзя передавать
экспертам до их независимых ответов или называть gold-разметкой.

```bash
python -m williams_ai.review_drafts \
  --pending-queue /private/market_review_queue.jsonl \
  --private-book-index /private/books.sqlite3 \
  --private-output /private/analyst_drafts_not_expert_labels.jsonl
```

Источник проверяется по metadata исходного приватного индекса и контрольной
сумме текстового содержимого страницы. Само совпадение metadata не доказывает
точность извлечения, смысловую правильность или качество рисунков. Статус
UNVERIFIED_EXTRACTION и непросмотренный OCR остаются явными; исходные
тексты страниц не экспортируются. Отсутствующая текстовая страница требует
визуальной проверки; её не заменяют ответом карточки автоматически.

В фактической выборке три задания ссылаются на COURSE PDF 56: это графическая
страница без извлечённого текста. Оригинальный PDF отдельно проверен по
SHA256 и рисунок просмотрен помощником; машинное описание сохранено отдельно,
без объявления независимой человеческой приёмки или изменения исходного индекса.

Контекст реального токенизатора Qwen3-4B для проверенного графического
примера составил 1613 токенов. Поэтому стандартный лимит LoRA увеличен
с 1024 до 4096; длинные примеры по-прежнему отклоняются без обрезки.
