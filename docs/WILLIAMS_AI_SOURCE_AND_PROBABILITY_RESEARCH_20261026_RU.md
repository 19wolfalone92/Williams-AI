## Область изменений
Только `19wolfalone92/Williams-AI`. Никаких биржевых команд, API-ключей, фонового GPU-обучения, изменения весов и копирования приватных книг в публичный репозиторий.

### Навигация по источникам
`williams_ai.research_source_router.source_route(question)` выбирает **только** записи `REVIEWED_PAGES` из канонического `knowledge/SOURCE_RULE_CARDS.json`, с PDF страницами и ID правил. Наличие указателя не означает, что модель прочитала/поняла оригинал. Для ответа нужно затем открыть приватную страницу, проверить рисунок, применить правило к закрытым свечам и учесть различия TC1/NTD/TC2/COURSE. При сомнении — несколько конкурирующих гипотез, не биржевой ордер.

### Проверка однообразных ответов
`williams_ai.research_quality_audit.repeated_answers(rows)` диагностирует **одинаковые фактические тексты** при разных темах. Не вызывает модель; для проверки Qwen требуются её настоящие ответы, собранные с одинаковыми настройками/раздельным контекстом. Одинаковое `WAIT` не обязательно ошибка; нужны экспертные проверки смысла.

### Вероятности нелинейного рынка
`resolved_forecasts(rows)` даёт Brier, log loss и бины калибровки для трёх заранее объявленных исходов (UP/DOWN/RANGE). Исходы должны наступить ПОСЛЕ зафиксированного прогноза. Этот локальный модуль **не** проверяет независимую timestamp-подпись прогнозов и **не** строит калибратор. Нет оснований назначать произвольные 70% без проспективной статистики.

### GPU / LoRA
В `main` уже существуют `private_lora.py`, `lora_training.py`, `lora_integrity.py` и синтетический CPU optimizer test. GPU-QLoRA исследование добавляется отдельно и не меняет торговую систему. Исходный HF safetensors Qwen != телефонный GGUF. Обучение на GPU требует независимой проверенной разметки, законных прав на облачную обработку и отдельной проверки holdout.

**Пока нет GPU run, нельзя заявлять обученный адаптер или улучшение торгового качества.**
