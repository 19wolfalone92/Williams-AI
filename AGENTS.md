# AGENTS.md — обязательный порядок работы с Williams AI

Этот файл обязателен для AI-агентов и автоматизированных помощников, изменяющих код в репозитории `19wolfalone92/Williams-AI`. Требования пользователя имеют приоритет. При неопределённости остановить изменения и сообщить об ограничении.

## 1. Строгая изоляция проектов
- Этот репозиторий — **только Williams AI**. Всё обучение, исследование, оценки Qwen/GGUF, исторические эксперименты и AI-функции выполнять здесь.
- Исходный `19wolfalone92/Williams` (Williams Bot 2.1) **не трогать** в процессе работы над Williams AI.
- Не копировать изменения между репозиториями и не объединять их PR/ветки автоматически; отдельная явная команда пользователя необходима для любой межпроектной интеграции.

## 2. Один активный автор изменений
- **Не более одной активной сессии/чата/агента, записывающего код в Williams-AI, в каждый момент времени.**
- Перед записью установить, что текущая сессия назначена единственной активной пользователем или действующим координатором. Если другая сессия потенциально редактирует те же файлы или владение неясно — остановить запись, уточнить владельца.
- Наличие многочисленных старых draft PR не равно множеству активных писателей. Отсутствие выполняющихся GitHub Actions не доказывает эксклюзивную запись.
- Автоматические GitHub Actions могут тестировать параллельно; учитывайте их результаты до слияния.
- Это координационная политика, **не техническая блокировка** другого чата.

## 3. Preflight перед каждой записью
1. Перечитать актуальный `main` SHA и HEAD текущей ветки.
2. Просмотреть открытые PR (особенно текущую линию обучения AI), пересечения файлов и запущенные/ожидающие CI.
3. Выбрать только один активный поток интеграции. Изучить, не реализована ли уже та же функция в ранее созданном PR.
4. До записи повторно проверить целевой HEAD; если он изменился, перечитать diff и согласовать конфликт.
5. При несовместимых PR, чужих новых изменениях или неясном владении — **не перезаписывать** код; сообщить проблему.

## 4. Отдельные ветки, проверка, последовательная интеграция
- Не коммитить прямо в `main`. Создать ветку от актуального `main` либо продолжить согласованную существующую ветку.
- Не использовать force-push, `reset --hard`, слепой cherry-pick пачкой, перезапись чужой работы.
- Каждая логическая серия изменений должна иметь PR с базовым SHA, списком затронутых компонентов, фактически пройденными тестами и рисками.
- Проверить diff, пересечение с существующими PR, соответствующие CI/тесты и отсутствие скрытых регрессий.
- **Не сливать** PR с красными/неизвестными обязательными проверками или неустранёнными конфликтами.
- Сливать PR **строго последовательно**, каждый раз актуализируя `main` и следующий PR. Не трактовать 31 открытый PR как готовые к автоматическому слиянию.

## 5. Научная добросовестность и защита капитала
- Отличать обученные веса модели от программной логики и истории сигналов; не утверждать, что Qwen дообучена, без доказательств.
- Сохранять no-lookahead, неизменность train/test split, независимый walk-forward, комиссии/проскальзывание, сравнение с baseline, отчёт о воздержании от сигналов.
- Многомиллионное число прогонов не подтверждает само по себе прибыльность или понимание рынка.
- До отдельного разрешения пользователя — только исследование/paper/demo в разрешённых границах; **никаких реальных ордеров и включения live-торговли**.
- Не сохранять API-ключи, токены, приватные данные или материалы первоисточников без соответствующих прав.

## 6. Итоговый отчёт
Указывать репозиторий, ветку, commit SHA/PR, реальные результаты проверок и ограничения, что осталось незавершённым и подтверждение «Williams Bot 2.1 не изменён». После команды пользователя «Стоп» не продолжать запись без новой команды.
